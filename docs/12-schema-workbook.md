## 1. ทำไมต้องเป็น Excel ไม่ใช่เอกสาร .md

| ปัญหาของเอกสาร .md | ไฟล์ Excel แก้ยังไง |
|---|---|
| ทีมอ่านได้แต่แก้ไม่ได้ ต้องบอกกลับมาเป็นข้อความ | พิมพ์ทับในช่องได้เลย |
| โครงสร้างกระจายอยู่ 11 ไฟล์ ต้องเปิดหลายที่ | อยู่ในไฟล์เดียว 12 แท็บ |
| ตัวเลขที่ผมตั้งเองปนกับข้อเท็จจริง แยกไม่ออก | **ทำสีแดงไว้ทุกจุด** ที่ยังไม่มีใครยืนยัน |
| จำนวนตารางในเอกสารไม่ตรงกัน (07 บอก 15, 09 บอก 16, 11 บอก 17) | นับใหม่จากของจริง = **20 รายการ** และบอกไว้ในไฟล์ว่าเอกสารเดิมไม่ตรงกัน |

**ไฟล์นี้เป็นต้นฉบับของโครงสร้างหลังบ้านนับจากนี้** — ถ้าแก้ในไฟล์แล้วไม่ตรงกับ `.md` ให้ยึดไฟล์ Excel

## 3. ความหมายของสี

| สี | หมายถึง |
|---|---|
| 🟡 **เหลือง** | ช่องที่ตั้งใจให้ทีมแก้ — SLA อัตราภาษี วงเงิน ชื่อฟิลด์ ฯลฯ |
| ⬜ **เทา** | ค่าที่ระบบใช้เป็นคีย์หรือคำนวณเอง แก้ได้แต่ต้องบอกก่อน เพราะกระทบโค้ด |
| 🔵 **ฟ้า** | ตาราง `Price_Requests` / `Quotations` / `Payment_Requests` / `Doc_Bundles` และคอลัมน์เรื่องซื้อเงินสด · ไดรฟ์กลาง · รวมไฟล์ ที่เพิ่งเพิ่ม ยังไม่ผ่านตาทีม |
| 🔴 **แดง** | **ค่าที่ผมตั้งเองและยังไม่มีใครยืนยัน** — ถ้าไม่แก้ ระบบจะใช้ค่านี้จริง |

สีแดงคือสิ่งสำคัญที่สุดในไฟล์ — เป็นการแยกให้ชัดว่าอะไรคือข้อเท็จจริงจากหน้างาน
และอะไรคือค่าที่ผมเลือกเองเพื่อให้ระบบเดินได้

## 4. คอลัมน์ «มาจากไหน» ในพจนานุกรมข้อมูล

คอลัมน์นี้มีค่ามากที่สุดในแท็บพจนานุกรม เพราะตอบคำถามว่า **คนต้องพิมพ์เองแค่ไหน**

| ค่า | หมายความว่า |
|---|---|
| `ดึงจาก B1` | ระบบดึงมาให้ ไม่มีใครพิมพ์ |
| `คนกรอก` | ต้องมีคนพิมพ์จริง — ทุกช่องนี้คือภาระของผู้ใช้ |
| `ระบบสร้าง/คำนวณ` | ระบบออกให้เอง (เลขที่เอกสาร เวลา สถานะ) |
| `คัดลอกจากเอกสารต้นทาง` | ดึงจากเอกสารก่อนหน้า เช่น จำนวนในใบเสนอราคาที่คัดจากใบขอราคา |

**กรองคอลัมน์นี้เป็น «คนกรอก» แล้วนับดู** จะเห็นทันทีว่าระบบขอให้คนพิมพ์กี่ช่อง —
ถ้าช่องไหนควรดึงมาได้แต่ยังให้พิมพ์อยู่ นั่นคือจุดที่ต้องแก้ก่อนขึ้นระบบ

## 5. สิ่งที่ต้องทำต่อ

1. เปิดแท็บ **ประเด็นค้าง** — 41 ประเด็น เรียงตามความสำคัญได้
2. กรอกช่อง **«คำตอบของทีม»** และเปลี่ยน **«สถานะ»** เป็น *ตัดสินใจแล้ว*
3. แต่ละแผนกดูแท็บของตัวเองตามตารางในข้อ 2
4. ส่งไฟล์กลับมา — **ระบบจะถูกสร้างตามไฟล์นี้**

> ตัวเลขสรุปในแท็บ «เริ่มที่นี่» และ «ประเด็นค้าง» เป็นสูตร Excel จริง
> กรอกคำตอบแล้วตัวนับ *รอตัดสินใจ / ตัดสินใจแล้ว* จะขยับเอง ใช้ติดตามความคืบหน้าได้

### หมายเหตุเรื่องสูตร

เครื่องที่ผมสร้างไฟล์นี้รัน LibreOffice ไม่ได้ (ทดสอบกับไฟล์ 3 ช่องก็ยัง timeout)
จึง**คำนวณสูตรล่วงหน้าให้ไม่ได้** — แต่จัดการไว้แล้ว 2 ชั้น:

1. ตั้ง `fullCalcOnLoad` ไว้ในไฟล์ → **Excel และ Google Sheets จะคำนวณให้เองทันทีที่เปิด**
2. ตรวจทุกสูตรด้วยการคำนวณคู่ขนานใน Python แล้วเทียบผลลัพธ์ — ทุกช่วงอ้างอิงถูกต้อง
   ไม่มีช่วงไหนกินแถวหมายเหตุด้านล่างเข้าไป และทุก `COUNTIF` คืนค่าที่สมเหตุผล

ค่าที่สูตรจะแสดงเมื่อเปิดไฟล์: 20 ตาราง · 390 คอลัมน์ · 17 ขั้นตอน · 6 เอกสารบังคับ ·
44 กฎ (บล็อก 38 / เตือน 6) · 42 ค่าตั้งต้น · 41 ประเด็นรอตัดสินใจ · SLA รวม 912 ชม.
**ถ้าเปิดแล้วตัวเลขไม่ตรงกับนี้ แปลว่ามีคนแก้ข้อมูลไปแล้ว ซึ่งเป็นเรื่องปกติ**

## 6. สร้างไฟล์นี้ใหม่ได้อย่างไร

ไฟล์ Excel ถูกสร้างจากสคริปต์ ไม่ได้พิมพ์มือ — ถ้าโครงสร้างในเอกสารเปลี่ยน ให้แก้สคริปต์แล้วสร้างใหม่

```bash
pip install openpyxl
python3 tools/build-schema-xlsx.py
```

สคริปต์มีการตรวจในตัว: ถ้าจำนวนแถวไม่ตรงกับช่วงที่สูตรอ้างถึง จะหยุดทันทีไม่ยอมสร้างไฟล์
(นี่คือกลไกที่จับได้ว่าสูตรกินแถวหมายเหตุเข้าไปในรอบก่อน)

> **ระวัง:** ถ้าทีมแก้ไฟล์ Excel แล้วส่งกลับมา **ห้ามรันสคริปต์ทับ** — จะลบสิ่งที่ทีมแก้ทั้งหมด
> ให้ย้ายคำตอบของทีมเข้าสคริปต์ก่อน แล้วค่อยสร้างใหม่
