# 03 — หน้าจอและสิทธิ์แต่ละแผนก

**สำหรับหัวหน้าแผนกตรวจ** ว่าทีมตัวเองเห็นอะไร แก้อะไรได้ และอะไรที่แก้ไม่ได้

**หลักการ:** ทุกคนเปิดเข้ามาต้องเห็น 3 อย่างในหน้าแรกภายใน 5 วินาที —
**อะไรค้างที่ฉัน · อะไรเลยกำหนด · ฉันรออะไรจากใคร**

---

## 1. หน้าจอที่ทุกคนใช้ร่วมกัน

### 1.1 หน้าแรก — คิวงานของฉัน

```
┌──────────────────────────────────────────────────────────────────┐
│ MGS DocHub      คิวของฉัน │ ทุกดีล │ รายงาน      คุณสมชาย (SR)  │
├──────────────────────────────────────────────────────────────────┤
│  ⚡ ค้างที่ฉัน 4      ⏰ เลยกำหนด 1      👀 รอคนอื่น 7            │
├──────────────────────────────────────────────────────────────────┤
│ ค้างที่ฉัน                                                        │
│  D-26-0042  กุ้ง 16/20  ABC Foods   รอ PO ซัพเซ็นกลับ    2 วัน ⚠ │
│  D-26-0051  ปลาหมึก     Thai Frozen รอกรอกเลข PO         4 ชม.   │
├──────────────────────────────────────────────────────────────────┤
│ รอคนอื่น                                                          │
│  D-26-0038  กุ้งขาว     รอ QC ตรวจรับ (คุณสมหญิง)        6 ชม.   │
│  D-26-0033  ปลาแซลมอน   รอ AC ทำจ่าย (คุณวิภา)           1 วัน   │
└──────────────────────────────────────────────────────────────────┘
```

**"รอคนอื่น" คือช่องที่ตัดคำถามในกลุ่มแชทออกไป** — เห็นเองว่างานอยู่ที่ใคร ไม่ต้องถาม

### 1.2 หน้าดีล — ทุกอย่างของ PO นี้อยู่หน้าเดียว

```
D-26-0042 · PO 4500012345 · ABC Foods · กุ้งแช่แข็ง 16/20 · ฿130,000
สถานะ: QC ตรวจรับ  ·  ผู้ถืองาน: คุณสมหญิง (QC)  ·  ค้าง 6 ชม. / SLA 24 ชม.
─────────────────────────────────────────────────────────────────────
ความคืบหน้า
 ✅ 1 เช็คราคา    ✅ 2 ตรวจตัวอย่าง   ⊘ 3 GM (ข้าม)   ✅ 4 คอนเฟิร์ม
 ✅ 5 PI          ⊘ 6 เปิดรหัส        ✅ 7 เปิด PO     ✅ 8 อนุมัติภายใน
 ✅ 9 ซัพเซ็นกลับ ✅ 10 จองรถ         🔵 11 ตรวจรับ    ⬜ 12 GR
 ⬜ 13 ใบแจ้งหนี้ ⬜ 14 ส่งเอกสาร      ⬜ 15 ทำจ่าย      ⬜ 16 ใบเสร็จ  ⬜ 17 ปิด
─────────────────────────────────────────────────────────────────────
เอกสาร                                  เจ้าของ    สถานะ
 PI                                      SR        ✅ อนุมัติแล้ว  [ดู]
 PO                                      SR        ✅ อนุมัติแล้ว  [ดู]
 PO ที่ซัพเซ็นกลับ                        SR        ✅ อัพโหลดแล้ว [ดู]
 Pattern label                            SR        ⊘ ไม่ต้องมี
 ผลตรวจรับ / RC                           QC        🔵 รออัพโหลด   [อัพโหลด]
 GR                                       WH        ⬜ รอ
 Invoice                                  AC        ⬜ รอ
 สลิป / Swift                             AC        ⬜ รอ
 ใบเสร็จรับเงินตัวจริง                     AC        ⬜ รอ
─────────────────────────────────────────────────────────────────────
3-Way check: ยังไม่พร้อม — ขาด GR, Invoice
ประวัติ (ใครทำอะไรเมื่อไหร่)                                  [ดูทั้งหมด]
```

**หน้านี้หน้าเดียวแทนการเปิด 5 เครื่องมือ** — และเป็นคำตอบของคำถาม "เอกสารครบหรือยัง"

### 1.3 ค้นหา

พิมพ์อะไรก็ได้: เลขดีล · **เลข PO จาก SAP** · ชื่อซัพ · เลข Invoice · เลข tracking ไปรษณีย์
→ ไปที่หน้าดีลนั้นทันที

## 2. แยกตามแผนก

### 2.1 Sourcing (SR)

| กรอก/แก้ได้ | ดูได้เท่านั้น | ทำไม่ได้ |
|---|---|---|
| สร้างดีล, ข้อมูลซัพ, สินค้า, ยอดเงิน | ผลตรวจ QC | แก้ผลตรวจ QC |
| เลข PO จาก SAP, payment condition | GR ของ WH | อัพโหลด GR แทน WH |
| Effective date, วันนัดรับของ | สลิป/ใบเสร็จของ AC | อนุมัติ PO ของตัวเอง |
| อัพโหลด PI, PO, PO ซัพเซ็นกลับ, Pattern label | ผล 3-way | แก้ไขเอกสารที่อนุมัติแล้ว (ต้องอัพโหลด version ใหม่) |
| ส่งขออนุมัติ, ขอเปิดรหัสสินค้า | | ปิดรายการ |

**หน้าจอเพิ่มเติม:** รายการที่ต้องตามซัพ (ใบแจ้งหนี้/เอกสารค้าง) พร้อมวันครบกำหนดตาม payment condition

### 2.2 QC

| กรอก/แก้ได้ | ดูได้เท่านั้น | ทำไม่ได้ |
|---|---|---|
| ผลตรวจตัวอย่าง (ผ่าน/ไม่ผ่าน + เหตุผล) | ข้อมูล PO, ซัพ, วันนัดรับ | **ไม่เห็นราคาและยอดเงิน** |
| ผลตรวจรับ + จำนวนที่รับได้/ปฏิเสธ | GR | แก้จำนวนใน GR |
| แนบรูปถ่าย | | ปิดรายการ / ปลดล็อกการจ่ายเงิน |
| เปิดเรื่องเคลม | | |

**ทำไม QC ไม่เห็นราคา:** แยกหน้าที่ตรวจคุณภาพออกจากเรื่องเงิน เพื่อให้ผลตรวจไม่ถูกกดดันด้วยมูลค่าของล็อต

**หน้าจอเพิ่มเติม:** คิวตรวจเรียงตาม SLA + วันนัดรับของล่วงหน้า (ไม่ต้องรอ SR แจ้ง)

### 2.3 Logistics (LS)

| กรอก/แก้ได้ | ดูได้เท่านั้น | ทำไม่ได้ |
|---|---|---|
| วันจองรถ, ข้อมูลรถ/คนขับ | PO, ซัพ, สินค้า | ไม่เห็นยอดเงิน |
| ยืนยันเปิดรหัสสินค้าใน SAP แล้ว | ผลตรวจ QC | แก้ผลตรวจ |

**หน้าจอเพิ่มเติม:** รายการที่ต้องจองรถภายใน 7 วัน + คิวขอเปิดรหัสสินค้า

### 2.4 Warehouse (WH)

| กรอก/แก้ได้ | ดูได้เท่านั้น | ทำไม่ได้ |
|---|---|---|
| จำนวนที่รับเข้าคลัง, เลข GR จาก SAP | PO, วันนัดรับ, ผลตรวจ QC | ไม่เห็นยอดเงิน |
| อัพโหลด GR | | แก้ผลตรวจ QC |
| หมายเหตุสภาพสินค้า | | ปิดรายการ |

**หน้าจอเพิ่มเติม:** ของที่จะเข้าใน 7 วันข้างหน้า (แผนกำลังคน)

### 2.5 Accounting (AC)

| กรอก/แก้ได้ | ดูได้เท่านั้น | ทำไม่ได้ |
|---|---|---|
| อัพโหลด Invoice + ยอด | **ทุกอย่างต้นน้ำ** (PO, QC, GR) | **แก้ข้อมูลต้นน้ำไม่ได้เลย** |
| อัพโหลด ใบลดหนี้, สลิป/Swift | | ปลดล็อกเรื่องเคลม (QC เท่านั้น) |
| อัพโหลด/บันทึกใบเสร็จตัวจริง | | แก้ผลตรวจ QC หรือจำนวน GR |
| บันทึกผลตรวจ 3-way + เหตุผล | | |
| ปิดรายการ | | |

**ทำไม AC แก้ข้อมูลต้นน้ำไม่ได้:** ถ้าราคา PO ผิด ต้องให้ SR แก้ ถ้าจำนวนรับผิด ต้องให้ WH/QC แก้
การให้บัญชีแก้ข้อมูลต้นน้ำเองเป็นสาเหตุอันดับหนึ่งที่ทำให้ audit trail ใช้ไม่ได้

**หน้าจอเพิ่มเติม (สำคัญที่สุดสำหรับ AC):**

```
┌─ พร้อมบันทึกบัญชี (8) ────────────────────────────────────────┐
│ D-26-0031  ฿84,000   PO+INV+GR ครบ ยอดตรง        [ปิดรายการ] │
├─ ยังไม่พร้อม (12) ────────────────────────────────────────────┤
│ D-26-0042  ฿130,000  ขาด GR, Invoice          → แจ้ง WH, SR  │
│ D-26-0038  ฿76,000   ยอด Invoice เกิน PO ฿2,000  → แจ้ง SR   │
│ D-26-0029  ฿45,000   มีเคลมค้าง รอใบลดหนี้      → แจ้ง QC    │
├─ รอเอกสารตัวจริง (5) ─────────────────────────────────────────┤
│ D-26-0025  ใบเสร็จ  EMS EX123456789  ส่ง 5 วันแล้ว  [ตามเรื่อง]│
└───────────────────────────────────────────────────────────────┘
```

### 2.6 GM / หัวหน้าแผนก

- **อนุมัติ** — เปิดจากมือถือ เห็นเอกสารและยอด กด อนุมัติ/ไม่อนุมัติ (ไม่อนุมัติต้องใส่เหตุผล)
- **ภาพรวมคอขวด** — stage ไหนค้างเยอะสุด นานสุด ใครถือ
- ดูได้ทุกดีล แก้ไม่ได้ (ยกเว้นการอนุมัติ)

## 3. ตารางสิทธิ์รวม

`C` สร้าง · `R` ดู · `U` แก้ · `A` อนุมัติ · `—` ไม่มีสิทธิ์

| หน้าที่ | SR | SR Head | QC | QC Head | LS | WH | AC | AC Head | GM |

| ยอดเงิน / ราคา | R U | R U | **—** | **—** | **—** | **—** | R U | R U | R |
| อัพโหลด PI / PO | C U | C U | — | — | — | — | R | R | R |
| อนุมัติ PO | — | **A** | — | — | — | — | — | — | **A** |
| ผลตรวจ QC | R | R | C U | C U A | R | R | R | R | R |

| จองรถ | R | R | R | R | **C U** | R | — | — | R |

**แถว "ยอดเงิน / ราคา" มีเครื่องตรวจอัตโนมัติคุมอยู่ ไม่ได้ฝากไว้กับความจำของคนเขียนโค้ด** —
ท้ายชุดทดสอบ `tools/smoke.js` จะสวมบทบาท QC · โลจิสติกส์ · คลัง แล้วเปิด**ทุกหน้า ทุกแท็บ
ทุกใบ PO ทุกใบคำร้อง ทุกการแจ้งเตือน** (414 จุดตรวจ) ถ้าเจอยอดเงินแม้จุดเดียว ชุดทดสอบจะแดง
พร้อมบอกว่าหลุดที่หน้าไหนและข้อความรอบ ๆ ว่าอะไร

เขียนขึ้นเพราะเคยพลาดมาแล้วจริง — การ์ด "แผนกก่อนหน้าส่งอะไรมาให้คุณ" และบรรทัดประวัติ
เคยโชว์ยอดใบแจ้งหนี้ให้ QC เห็น เพราะฟีเจอร์ที่เพิ่มทีหลังไม่ได้ผ่านประตู `money()` ที่มีอยู่แล้ว
การไล่แก้ทีละจุดคือแก้อาการ เครื่องตรวจตัวนี้คือสิ่งที่ทำให้ของใหม่รอบหน้าทำรั่วซ้ำไม่ได้
บทบาทที่ห้ามเห็นเงินยัง**ไม่เห็นเมนู ตั้งค่าระบบ** ด้วย เพราะทะเบียนซื้อเงินสดอยู่ในนั้น

**ผู้ดูแลระบบ (IT)** มีสิทธิ์จัดการผู้ใช้และตั้งค่า แต่**ไม่อยู่ในสายอนุมัติ** — ผู้ดูแลที่อนุมัติเอกสารได้เองทำให้
ระบบตรวจสอบเป็นแค่การตกแต่ง

## 4. กฎแยกหน้าที่ (บังคับด้วยโปรแกรม ไม่ใช่ด้วยความไว้ใจ)

| กฎ | เหตุผล |
|---|---|
| คนสร้างดีลอนุมัติดีลตัวเองไม่ได้ | กันการสั่งซื้อโดยไม่มีคนตรวจ |
| คนอัพโหลด Invoice ปิดรายการเองไม่ได้ | กันการจ่ายเงินโดยไม่มีคนสอบ |
| QC ที่ตรวจ ปลดล็อกเคลมของตัวเองไม่ได้ (ต้อง QC Head) | กันการยกเว้นคุณภาพเองเงียบ ๆ |
| SR แก้ผลตรวจ QC หรือจำนวน GR ไม่ได้ | ให้เจ้าของข้อมูลเป็นคนแก้เท่านั้น |
| AC แก้ราคา PO ไม่ได้ | ถ้าผิดต้องให้ SR แก้ที่ต้นทาง |

ทุกครั้งที่มีคนพยายามทำสิ่งที่ไม่มีสิทธิ์ **ระบบบันทึกลง `Stage_Log` ด้วย** แม้จะถูกปฏิเสธ

**หมายเหตุสำหรับทีมเล็ก:** บางกรณีอาจต้องยืดหยุ่น (เช่นคนลาแล้วไม่มีคนแทน) ให้ทำเป็น
**การยกเว้นที่บันทึกเหตุผลไว้** ไม่ใช่การเปิดช่องถาวรในตารางสิทธิ์

## 5. อุปกรณ์ที่ใช้

| แผนก | อุปกรณ์หลัก | ข้อควรออกแบบ |
|---|---|---|
| SR, AC | คอมพิวเตอร์ | ตารางหลายคอลัมน์ คีย์เร็ว |
| QC | **มือถือ/แท็บเล็ต** | ปุ่มใหญ่ ถ่ายรูปเข้าระบบตรงจากกล้อง ใช้ในห้องเย็นได้ |
| WH | **มือถือ** | กรอกน้อยที่สุด สแกน/ถ่ายรูปเป็นหลัก |
| LS | มือถือ + คอม | ปฏิทินจองรถ |
| GM | **มือถือ** | หน้าอนุมัติต้องกดจบใน 2 แตะ |

QC และ WH ทำงานยืน ใส่ถุงมือ ในที่เย็น — หน้าจอของสองแผนกนี้ต้องออกแบบเพื่อมือถือเป็นหลัก
ไม่ใช่ย่อหน้าจอคอมมาใส่
