## 0. สรุปสำหรับผู้บริหาร

ทั้ง 4 ข้อแก้ปัญหาเดียวกันคือ **"หลักฐานอยู่นอกระบบ"**

| ของเดิม | หลังทำ |
|---|---|
| ของซื้อเงินสดไม่เข้าระบบเลย บิลอยู่ในลิ้นชัก | มีเลข `CS-26-xxxx` เหมือน PO เดินในโฟลว์เดียวกัน |
| ใครข้าม QC ก็รู้กันปากเปล่า | ข้าม QC ได้ แต่ต้องพิมพ์เหตุผลและชื่อผู้อนุมัติ ลบไม่ได้ |
| ไฟล์อยู่ไดรฟ์ `M:` เครื่องส่วนตัว และแชท | ไดรฟ์กลางที่เดียว ระบบตั้งชื่อและวางโฟลเดอร์ให้ |
| ตรวจย้อนหลังต้องเปิด 8 ไฟล์ | ปิดงานแล้วได้ไฟล์รวมเล่ม 1 ไฟล์อัตโนมัติ |
| กดปุ่ม "เสร็จ" แล้วจบ ไม่รู้ว่าแนบอะไรไปหรือยัง | ทุกขั้นต้องผ่านป๊อปอัปแนบไฟล์ + หมายเหตุก่อนส่งต่อ |
| SR แจ้งยอดที่ต้องจ่ายในไลน์ | ฟอร์มขอทำจ่าย ยอดเงิน + Effective date เป็นช่องบังคับ ส่งเข้าสายอนุมัติ |

**ข้อแลกเปลี่ยนที่ต้องตัดสินใจ (สำคัญ)** — ข้อ 3 ขัดกับการประหยัดพื้นที่ที่วางไว้ใน
[docs/07 §3.3](07-system-blueprint.md) ซึ่งประหยัดได้มากที่สุดจากการ *ไม่* เก็บไฟล์รวม (~1,750 MB/เดือน)
ทางออกที่ทำไว้: เก็บต้นฉบับต่ออีก **90 วัน** แล้วลบเฉพาะใบที่รวมเล่มไปแล้ว
ถ้าบัญชีต้องเก็บต้นฉบับตามกฎหมาย → ปิดการลบ และยอมรับพื้นที่ที่เพิ่มขึ้น (แก้ได้ในหน้าตั้งค่า)

## 1. รายการซื้อเงินสด (Non-PO / Direct Purchase)

### 1.1 ทำไมต้องมี

ของสดหน้าตลาด ค่าขนส่งย่อย ของด่วนที่ร้านไม่รับเครดิต — จ่ายไปแล้วจริง แต่ไม่มีที่ให้บันทึก
ผลคือบัญชีปิดงบไม่ตรง และผู้ตรวจสอบถามหาหลักฐานไม่ได้

### 1.2 User Stories

| ID | ในฐานะ | ฉันต้องการ | เพื่อ | เกณฑ์ยอมรับ |
|---|---|---|---|---|
| CS-1 | จัดซื้อ | เพิ่มรายการซื้อที่ไม่ได้เปิด PO | บันทึกของที่จ่ายสดไปแล้ว | ได้เลข `CS-26-xxxx` · แสดงในรายการเดียวกับ PO พร้อมป้าย `CASH` |
| CS-2 | จัดซื้อ | ระบุเหตุผลที่ไม่เปิด PO | ตอบผู้ตรวจสอบได้ | ช่องบังคับ · ว่างแล้วบันทึกไม่ได้ (กฎ C1) |
| CS-3 | จัดซื้อ | ระบุว่าล็อตนี้ไม่ต้องให้ QC ตรวจ | ผักสดที่ตรวจหน้างานแล้วไม่ต้องรอ | ติ๊ก 1 ช่อง · ระบบข้ามขั้น QC ให้ |
| CS-4 | หัวหน้า QC | เห็นทุกใบที่ข้าม QC พร้อมเหตุผลและผู้อนุมัติ | คุมไม่ให้ข้ามพร่ำเพรื่อ | ทะเบียนในหน้าตั้งค่า → แท็บ *ไดรฟ์และการรวมไฟล์* · แก้ย้อนหลังไม่ได้ |
| CS-5 | บัญชี | เห็นว่าจ่ายจากเงินสดย่อยหรือใครสำรองจ่าย | ตั้งเบิกคืนถูกคน | ช่อง *จ่ายจาก* 3 ตัวเลือก · ลงในงวดจ่ายอัตโนมัติเป็นสถานะจ่ายแล้ว |
| CS-6 | ผู้บริหาร | กันไม่ให้ใช้ช่องทางเงินสดซื้อของก้อนใหญ่ | เลี่ยงการหลบสายอนุมัติ | เกิน `CASH_LIMIT` บันทึกไม่ได้ ต้องเปิด PO (กฎ C4) |

### 1.3 กฎตรวจสอบก่อนบันทึก

| กฎ | เงื่อนไข | ผล |
|---|---|---|
| C1 | ไม่ระบุเหตุผลที่ไม่เปิด PO | **บล็อก** |
| C2 | วันที่จ่ายเป็นวันข้างหน้า | **บล็อก** — บันทึกได้เมื่อจ่ายจริงแล้ว |
| C3 | ติ๊กข้าม QC แต่ไม่ระบุเหตุผล/ผู้อนุมัติ | **บล็อก** |
| C4 | ยอด > `CASH_LIMIT` (ตั้งต้น ฿50,000) | **บล็อก** — ต้องเปิด PO |
| C5 | ผู้ขาย / สินค้า / จำนวน / ยอดเงิน ว่าง | **บล็อก** |

### 1.4 ขั้นตอนที่รายการเงินสดต้องเดิน

รายการเงินสด **ข้ามขั้นจัดซื้อทั้งหมด (1–10)** เพราะซื้อไปแล้ว

```
ไม่ข้าม QC:   [11] QC ตรวจรับ → [12] รับเข้าคลัง+GR → [13] แนบบิล → [14] ส่งมอบเอกสาร → [17] ปิด
ข้าม QC:                        [12] รับเข้าคลัง+GR → [13] แนบบิล → [14] ส่งมอบเอกสาร → [17] ปิด
```

ขั้นทำจ่าย (15) ถูกทำเครื่องหมายจ่ายแล้วตั้งแต่บันทึก เพราะจ่ายสดไปแล้วหน้างาน

## 2. ไดรฟ์กลางที่เดียว (Centralized Shared Storage)

### 2.1 User Stories

| ID | ในฐานะ | ฉันต้องการ | เกณฑ์ยอมรับ |
|---|---|---|---|
| DR-1 | ทุกแผนก | อัพไฟล์จากหน้ารายการโดยไม่ต้องเปิด Drive | ไม่มีปุ่มไหนพาออกไปหน้า Drive |
| DR-2 | ทุกแผนก | ไม่ต้องตั้งชื่อไฟล์เอง | ระบบแสดงชื่อที่จะใช้ให้เห็นก่อนกดบันทึก |
| DR-3 | บัญชี | รู้ว่าไฟล์ของรายการหนึ่งอยู่ที่ไหนโดยไม่ต้องถาม | หน้ารายละเอียดแสดง path เต็มของโฟลเดอร์ |
| DR-4 | แอดมิน | ไม่มีใครสร้างโฟลเดอร์เองได้ | ระบบสร้างให้ตอนเปิดรายการเท่านั้น |

### 2.2 โครงสร้าง

```
MGS-Documents   (Shared drive — ไดรฟ์เดียวของทั้งบริษัท)
├── PO-2026/
│   └── PO-26-0042/
│       ├── PO-26-0042_PI.pdf
│       ├── PO-26-0042_PO_SIGNED.pdf
│       ├── PO-26-0042_QC_RC.pdf
│       ├── PO-26-0042_GR.jpg
│       ├── PO-26-0042_INVOICE.pdf
│       ├── PO-26-0042_SLIP_งวดที่1.jpg
│       └── PO-26-0042_ชุดเอกสารครบ.pdf      ← สร้างเมื่อปิดรายการ
└── CASH-2026/
    └── CS-26-0007/
        ├── CS-26-0007_INVOICE.jpg
        └── CS-26-0007_ชุดเอกสารครบ.pdf
```

**กติกาการตั้งชื่อ:** `<เลขรายการ>_<รหัสประเภทเอกสาร>.<นามสกุลเดิม>`
ไฟล์ซ้ำประเภทเดิม = ขึ้นเวอร์ชันใหม่ ไม่ทับของเดิม (`is_current`)

**สิทธิ์:** ไดรฟ์เป็นของ service account ของระบบ — คนเข้าถึงผ่านหน้าเว็บเท่านั้น
ไม่มีใครมีสิทธิ์ลบไฟล์ตรงในไดรฟ์ รวมถึงแอดมิน

## 3. รวมไฟล์อัตโนมัติเมื่อจบกระบวนการ (Auto-Merge)

### 3.1 User Stories

| ID | ในฐานะ | ฉันต้องการ | เกณฑ์ยอมรับ |
|---|---|---|---|
| MG-1 | บัญชี | ได้ไฟล์เดียวที่มีเอกสารครบชุดเมื่อปิดรายการ | สร้างอัตโนมัติ ไม่มีปุ่มให้กด |
| MG-2 | ผู้ตรวจสอบ | เอกสารเรียงตามลำดับขั้นตอน | ลำดับตาม `Doc_Templates.seq` |
| MG-3 | บัญชี | รู้ว่าไฟล์รวมมีอะไรอยู่ข้างใน | หน้ารายละเอียดแสดงรายชื่อทุกใบที่ถูกรวม |
| MG-4 | IT | ควบคุมพื้นที่ไม่ให้บวม | ลบต้นฉบับที่รวมแล้วหลัง `MERGE_KEEP_DAYS` (ตั้งต้น 90 วัน) ปิดได้ |

### 3.2 สิ่งที่ถูกรวมและลำดับ

1. เอกสารบังคับทุกใบตาม `Doc_Templates` (PI → PO เซ็นแล้ว → ผลตรวจ QC → GR → ใบแจ้งหนี้ → ใบเสร็จ)
2. ไฟล์ที่แนบรายขั้นจากป๊อปอัป (เรียงตามลำดับขั้น)
3. สลิป/Swift ทุกงวด
4. ใบอนุมัติข้าม QC (ถ้ามี)

ไฟล์ที่ไม่ใช่ PDF (รูปถ่าย GR, สลิปจากมือถือ) ถูกแปลงเป็นหน้า PDF ก่อนรวม
ทุกหน้ามีท้ายกระดาษบอก **ชื่อไฟล์ต้นฉบับ · ผู้อัพ · วันเวลา** เพื่อให้ย้อนกลับไปหาต้นฉบับได้

### 3.3 ผลกระทบด้านพื้นที่ — ต้องตัดสินใจ

| กรณี | พื้นที่/เดือน |
|---|---|
| ไม่รวมไฟล์ (แผนเดิม docs/07) | ~165 MB |
| รวมไฟล์ + เก็บต้นฉบับตลอดไป | ~330 MB |
| **รวมไฟล์ + ลบต้นฉบับหลัง 90 วัน (ค่าตั้งต้น)** | **~180 MB** |

> ตัวเลขนี้ประมาณจากอัตราปัจจุบัน ~40 PO/เดือน · เฉลี่ย 7 ใบ/PO — **ยังไม่มีใครยืนยัน** ต้องวัดจริงเดือนแรก

## 4. ป๊อปอัปแนบเอกสารประจำขั้น และการขออนุมัติจ่าย

### 4.1 ป๊อปอัปประจำทุกขั้น

ทุกครั้งที่กดปุ่มทำขั้นตอนให้เสร็จ ระบบเปิดป๊อปอัปก่อนเสมอ — ไม่ส่งต่อทันทีอีกต่อไป

| ID | ในฐานะ | ฉันต้องการ | เกณฑ์ยอมรับ |
|---|---|---|---|
| UP-1 | ทุกแผนก | แนบไฟล์ของขั้นตัวเองในป๊อปอัปเดียว | เปิดจากปุ่มของขั้นนั้น ไม่ต้องเลื่อนหา |
| UP-2 | ทุกแผนก | เขียนหมายเหตุติดขั้นนั้นไว้ | ช่องข้อความหลายบรรทัด · ขึ้นในหน้ารายละเอียดและในประวัติ |
| UP-3 | ระบบ | ไม่ให้ข้ามขั้นที่มีเอกสารบังคับโดยไม่แนบ | บล็อกพร้อมบอกว่าขาดใบไหน |
| UP-4 | ทุกแผนก | บันทึกได้แม้ขั้นนั้นไม่มีเอกสาร | ติ๊ก *ขั้นนี้ไม่มีเอกสารต้องแนบ* แล้วต้องเขียนหมายเหตุแทน |
| UP-5 | ทุกแผนก | เห็นชื่อไฟล์ที่ระบบจะตั้งให้ก่อนกดบันทึก | แสดงสดขณะพิมพ์ |

### 4.2 ฟอร์มขออนุมัติทำจ่าย (ขั้น SR ส่งมอบเอกสาร)

| ID | ในฐานะ | ฉันต้องการ | เกณฑ์ยอมรับ |
|---|---|---|---|
| PR-1 | จัดซื้อ | ระบุ **ยอดเงินที่ต้องจ่าย** | ช่องบังคับ · ต้อง > 0 (กฎ S1) |
| PR-2 | จัดซื้อ | ระบุ **Effective date** | ช่องบังคับ · ห้ามย้อนหลัง (กฎ S4) · ลงเป็นวันครบกำหนดของงวดนั้น |
| PR-3 | จัดซื้อ | ติ๊กให้ข้อความนี้ไปพิมพ์ลงบนเอกสารที่แนบ | 1 ช่องติ๊ก · ปิดแล้วเก็บเป็นหมายเหตุแทน |
| PR-4 | จัดซื้อ | ดูตัวอย่างก่อนส่ง และแก้ข้อความได้ | กล่องตัวอย่างแก้ได้ · ปรับตำแหน่ง 4 แบบ ขนาด 3 ระดับ สี 3 แบบ |
| PR-5 | จัดซื้อ | ส่งให้หัวหน้าอนุมัติในปุ่มเดียว | งวดเปลี่ยนเป็น *รออนุมัติจ่าย* · แจ้งเตือนหัวหน้าทาง Lark |
| PR-6 | หัวหน้า | เห็นคำขอพร้อมเอกสารครบชุด | เอกสารในไดรฟ์ถูกแนบไปกับคำขออัตโนมัติ |
| PR-7 | บัญชี | มั่นใจว่าเอกสารต้นฉบับไม่ถูกแก้ | ข้อความที่ประทับสร้างเป็น**เวอร์ชันใหม่** ต้นฉบับยังอยู่ |

```
   ├─ ออกเลข CS-26-xxxx · สร้างโฟลเดอร์ในไดรฟ์กลาง
   ├─ สร้างงวดจ่าย 1 งวด สถานะ "จ่ายแล้ว" (จ่ายสดไปแล้ว)
   ├─ บันทึกเหตุผล + การข้าม QC ลง Stage_Log (ลบไม่ได้)
   │
   ├─ ข้าม QC?  ── ใช่ ──► เข้าขั้น "รับเข้าคลัง + GR"  + แจ้งหัวหน้า QC ให้รับทราบ
   │             ── ไม่ ─► เข้าขั้น "QC ตรวจรับ"
   ▼
เดินโฟลว์เดียวกับ PO ปกติจนปิดรายการ
```

### 5.2 ทุกขั้นตอน → ป๊อปอัป → รวมไฟล์

```
ผู้ใช้กดปุ่มของขั้นตัวเอง
   │
   ▼
ป๊อปอัป [แนบไฟล์]  [หมายเหตุ]  (แสดงชื่อไฟล์ที่ระบบจะตั้งให้ + โฟลเดอร์ปลายทาง)
   │
   ├─ ขั้นนี้มีเอกสารบังคับ และไม่แนบ ──► บล็อก
   ├─ ไม่มีเอกสาร → ติ๊ก "ไม่มีเอกสารต้องแนบ" + เขียนหมายเหตุ
   ▼
บันทึกไฟล์เข้าไดรฟ์กลาง (ตั้งชื่อ + วางโฟลเดอร์ให้)
   │
   ├─ เขียน Stage_Log · เขียน Documents
   ├─ ส่งงานต่อขั้นถัดไป + แจ้งเตือนเจ้าของขั้นถัดไป
   ▼
ขั้นสุดท้ายเสร็จ?
   │ ใช่
   ▼
รวมทุกไฟล์เป็น <เลขรายการ>_ชุดเอกสารครบ.pdf → เก็บในโฟลเดอร์เดียวกัน
   │
   ▼
ตั้งเวลาลบต้นฉบับที่รวมแล้วอีก 90 วัน (ปิดได้)
```

### 5.3 ขั้น SR ขอทำจ่าย

```
SR กด "ส่งเอกสาร + ขออนุมัติทำจ่าย"
   │
   ▼
ฟอร์ม:  [ยอดเงินที่ต้องจ่าย *]  [Effective date *]
        [✓] ประทับข้อความนี้ลงบนเอกสารที่แนบ
        [เอกสารที่จะประทับ ▾] [ตำแหน่ง ▾] [ขนาด ▾] [สี ▾]
        ┌─ ตัวอย่าง (แก้ข้อความได้) ─────────────┐
        │ ขออนุมัติทำจ่าย PO-26-0045            │
        │ ยอดที่ต้องจ่าย ฿122,500               │
        │ มีผลวันที่ 26/08/2026                 │
        └───────────────────────────────────────┘
   │
   ├─ ตรวจกฎ S1–S7 ──► ติด → แสดงทุกข้อ ไม่ส่ง
   ▼ ผ่าน
สร้างเอกสารเวอร์ชันใหม่ที่มีข้อความประทับ (ต้นฉบับยังอยู่)
   │
   ├─ งวดจ่าย → "รออนุมัติจ่าย" · วันครบกำหนด = Effective date
   ├─ ยอด > วงเงินอนุมัติ ? ──► ผู้บริหาร     ──┐
   │                        └─► หัวหน้าบัญชี ──┤
   ▼                                            ▼
ส่งงานไปขั้น "ทำจ่าย" ของบัญชี         แจ้งเตือน Lark พร้อมลิงก์เอกสารครบชุด
```
