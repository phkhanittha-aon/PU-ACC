# 19 — คู่มือติดตั้งและส่งมอบ Phase 1 (สำหรับ IT)

ระบบ **MGS Document Center** ช่วงทดลอง — ฐานข้อมูลเป็น Google Sheet · หน้าจอเป็น Apps Script Web App ·
แจ้งเตือนผ่าน Lark Bot API · ยังไม่เชื่อม API ของ SAP (Phase ถัดไป)

---

## 1. ของที่ต้องมีก่อนเริ่ม

| ของ | ใคร | หมายเหตุ |
|---|---|---|
| Google Workspace ของบริษัท | มีอยู่แล้ว | พนักงานทุกคนที่ร่วมทดลองต้องมีอีเมล `@mglobalsourcing.net` |
| Shared drive สำหรับเก็บเอกสาร | IT | อย่าใช้ My Drive ของคนใดคนหนึ่ง — คนนั้นลาออกแล้วไฟล์หายไปด้วย |
| Lark app (bot) | IT + Lark admin | ต้องได้ `app_id`, `app_secret` และเปิดสิทธิ์ส่งข้อความ |
| `chat_id` ของกลุ่มแจ้งเตือน | IT | เชิญ bot เข้ากลุ่มก่อน แล้วจึงอ่าน chat_id ได้ |

## 2. ติดตั้ง (ครั้งเดียว ~30 นาที)

**2.1 สร้างไฟล์**

1. สร้าง Google Sheet ใหม่ใน **Shared drive** (ไม่ใช่ My Drive ของใครคนหนึ่ง)
   ตั้งชื่อ `MGS Document Center — ฐานข้อมูล`
2. เมนู **ส่วนขยาย → Apps Script** — จะได้โปรเจกต์สคริปต์ที่ผูกกับ Sheet ใบนี้
3. เอาโค้ดเข้าโปรเจกต์ ด้วยวิธี **A** หรือ **B**

#### วิธี A — คัดลอกวาง (ไม่ต้องติดตั้งอะไร · แนะนำสำหรับครั้งแรก)

1. ในตัวแก้ไข จะมีไฟล์ `Code.gs` เปล่าอยู่แล้ว — เปิดไว้ก่อน ค่อยวางทับตอนถึงคิว
2. ไฟล์ `.gs` แต่ละไฟล์: กด **+ ข้าง Files → Script**
   แล้วตั้งชื่อ **ไม่ต้องพิมพ์ `.gs`** (พิมพ์ `Flow` ระบบเติม `.gs` ให้เอง)
3. `index.html`: กด **+ → HTML** แล้วตั้งชื่อ **`index`** — ห้ามพิมพ์ `.html`
   > ชื่อต้องเป็น `index` เป๊ะ ๆ เพราะ `Code.gs` เรียก `createTemplateFromFile('index')`
   > ตั้งชื่ออื่นแล้วจะเปิดเว็บแอปไม่ขึ้น ฟ้องว่าหาไฟล์ไม่เจอ
4. `appsscript.json`: **สร้างใหม่ไม่ได้และไม่ต้องสร้าง** — ไฟล์นี้มีอยู่แล้วทุกโปรเจกต์ แค่ถูกซ่อนไว้
   ทำให้มันโผล่มาแล้ววางทับ (รายละเอียดข้างล่าง)

##### วาง `appsscript.json` ยังไง

ปุ่ม **+** ในตัวแก้ไขสร้างได้แค่ Script / HTML เท่านั้น ไม่มีตัวเลือก JSON —
เพราะไฟล์นี้เป็นของโปรเจกต์อยู่แล้ว หน้าที่เราคือ**เปิดให้เห็นแล้วแก้เนื้อหา**

1. กด **⚙ Project Settings** (รูปเฟือง แถบซ้าย)
2. ติ๊ก **"Show 'appsscript.json' manifest file in editor"**
3. กลับไปแถบ **Editor** (`< >`) — จะเห็น `appsscript.json` โผล่ในรายการไฟล์
4. คลิกเปิด **ลบเนื้อหาเดิมทั้งหมด** แล้ววางของเราทับ → **Save**

**ห้ามเปลี่ยนชื่อไฟล์** และ **ต้องเป็น JSON ที่ถูกต้อง** — พิมพ์ตกจุลภาคแล้วจะ Save ไม่ผ่าน
ตัวแก้ไขจะฟ้องตรงบรรทัดที่ผิด

**เนื้อหาแต่ละบรรทัดมีผลจริง**

| ค่า | ทำอะไร | ถ้าไม่ใส่ |
|---|---|---|
| `timeZone: Asia/Bangkok` | เวลาที่บันทึกใน History และวันครบกำหนด | เวลาเพี้ยนไป 7 ชม. วันครบกำหนดคลาดไปหนึ่งวัน |
| `runtimeVersion: V8` | ใช้ JavaScript รุ่นใหม่ | โค้ดรันไม่ได้ (โปรเจกต์ใหม่เป็น V8 อยู่แล้ว) |
| `oauthScopes` (6 ตัว) | สิทธิ์ที่ระบบขอจากผู้ใช้ | ระบบขอสิทธิ์กว้างเกินจำเป็น |
| `webapp` | ตั้งค่าเว็บแอปตอน deploy ด้วย clasp | ถ้า deploy จากหน้าจอ เลือกในกล่อง deploy แทนได้ |

`oauthScopes` ทั้ง 6 ตัวตรงกับของที่โค้ดเรียกใช้จริง ไม่มีเกิน

| scope | เพราะโค้ดใช้ |
|---|---|
| `spreadsheets` | `SpreadsheetApp` — ฐานข้อมูล |
| `drive` | `DriveApp` — เก็บเอกสารแนบ |
| `script.external_request` | `UrlFetchApp` — ยิง Lark |
| `script.scriptapp` | `ScriptApp` — ติดตั้งทริกเกอร์ |
| `userinfo.email` | `Session.getActiveUser()` — รู้ว่าใครล็อกอิน |
| `script.send_mail` | `MailApp` — อีเมลแจ้ง IT เมื่อระบบขัดข้อง |

> **หลังแก้ `oauthScopes` ระบบจะขอสิทธิ์ใหม่อีกรอบ** ตอนรันครั้งถัดไป — เป็นเรื่องปกติ กด Allow

**ถ้าไม่อยากแตะไฟล์นี้เลยก็ได้** — Apps Script เดาสิทธิ์จากโค้ดให้เอง แต่ต้องทำสองอย่างแทน
1. ตั้ง timezone เป็น `(GMT+07:00) Bangkok` ใน **Project Settings**
2. ตอน deploy เลือก *Execute as: Me* และ *Who has access: ทุกคนในโดเมน* ในกล่อง deploy

ผลลัพธ์ใช้งานได้เหมือนกัน ต่างแค่ระบบจะขอสิทธิ์กว้างกว่าที่จำเป็น

#### วิธี B — clasp (สำหรับ IT ที่จะอัปเดตโค้ดบ่อย)

**ก่อนอื่น** เปิด Apps Script API ที่ <https://script.google.com/home/usersettings>
(ปิดอยู่โดยค่าเริ่มต้น — ไม่เปิดแล้ว `clasp push` จะขึ้น `User has not enabled the Apps Script API`)

```bash
npm i -g @google/clasp
clasp login                      # ล็อกอินด้วยบัญชีบริษัท

# ใช้ clone ไม่ใช่ create เพราะสร้าง Sheet ไปแล้วในข้อ 1
# หา Script ID จาก ตัวแก้ไข → ⚙ Project Settings → Script ID
cd apps-script
clasp clone <SCRIPT_ID>
clasp push
```

> **อย่าใช้ `clasp create --type sheets`** — คำสั่งนั้นสร้าง Sheet **ใบใหม่**
> จะได้ไฟล์สองใบและโค้ดไปเกาะใบที่ผิด
>
> `clasp clone` จะดึง `appsscript.json` ของโปรเจกต์เปล่ามาทับของเรา
> หลัง clone ให้ `git checkout appsscript.json` เพื่อเอาของเรากลับมา แล้วค่อย `clasp push`
>
> `clasp clone` สร้าง `.clasp.json` ซึ่ง `.gitignore` กันไว้แล้ว — เป็นค่าเฉพาะเครื่อง ไม่ต้องขึ้น Git

**ตรวจว่าเข้าครบ**: ในตัวแก้ไขต้องเห็น **10 ไฟล์ `.gs` + `index.html` + `appsscript.json`**
แล้วกด **Save** หนึ่งครั้ง — ถ้ามีวงเล็บหรือเครื่องหมายคำพูดขาด ตัวแก้ไขจะขีดเส้นแดงให้เห็นทันที

**2.2 ตั้ง Script Properties** (ตัวแก้ไข Apps Script → ⚙ Project Settings → เลื่อนลงล่างสุด → **Script Properties → Add script property**)

|---|---|:--:|
| `SPREADSHEET_ID` | **ไม่ต้องกรอก** — ระบบเติมให้เองตอนกดเมนูติดตั้ง | — |
| `DRIVE_ROOT_ID` | สร้างโฟลเดอร์ใน Shared drive แล้วเปิดดู · เอาจาก URL | ✔ |
| `ADMIN_EMAIL` | อีเมลของ IT ที่จะรับแจ้งเมื่อระบบขัดข้อง — เลือกเอง | ✔ |
| `LARK_APP_ID` · `LARK_APP_SECRET` | Lark Developer Console → แอปของคุณ → Credentials & Basic Info | ✔ |
| `LARK_GROUP_CHAT_ID` | **กดเมนู "หา chat_id ของกลุ่ม Lark"** ในชีต | ✔ |

#### `DRIVE_ROOT_ID` — เอาจาก URL ของโฟลเดอร์

1. เปิด Google Drive → **Shared drives** → สร้างโฟลเดอร์ `MGS-Documents`
2. เปิดโฟลเดอร์นั้น แล้วดูที่ URL

```
https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz012345
                                       └────────── ค่านี้คือ DRIVE_ROOT_ID ──────────┘
```

> **ต้องตั้งค่านี้ก่อนกดเมนูติดตั้ง** — ถ้ายังไม่ตั้ง ระบบจะสร้างโฟลเดอร์ให้เองแต่ไปอยู่ใน
> **"ไดรฟ์ของฉัน" ของคนที่กดติดตั้ง** แปลว่าเอกสารของทั้งบริษัทไปอยู่ในไดรฟ์ส่วนตัวคนเดียว
> วันที่คนนั้นลาออกแล้วบัญชีถูกปิด ไฟล์หายไปพร้อมกัน
> (ระบบจะเตือนบนหน้าจอถ้าเกิดกรณีนี้ — ย้ายโฟลเดอร์ไป Shared drive แล้วแก้ค่าให้ตรงได้)

`SPREADSHEET_ID` ถ้าอยากดูเองก็อยู่ใน URL ของ Sheet ที่เดียวกัน:
`https://docs.google.com/spreadsheets/d/`**`<SPREADSHEET_ID>`**`/edit`

#### `LARK_APP_ID` · `LARK_APP_SECRET` — จาก Lark Developer Console

1. เข้า <https://open.larksuite.com/app> (หรือ <https://open.feishu.cn/app> ถ้าใช้ Feishu)
   ด้วยบัญชีที่มีสิทธิ์สร้างแอป — ถ้าเข้าไม่ได้ต้องให้ **Lark admin** ทำให้
2. **Create custom app** → ตั้งชื่อ เช่น `MGS Document Center`
3. เมนู **Credentials & Basic Info** → คัดลอก **App ID** และ **App Secret**
4. เมนู **Features → Bot** → เปิดใช้งาน (ไม่เปิด bot จะส่งข้อความไม่ได้)
5. เมนู **Permissions & Scopes** → เพิ่มสิทธิ์

   | สิทธิ์ | ใช้ทำอะไร |
   |---|---|
   | `im:message:send_as_bot` | ส่งข้อความในนาม bot |
   | `im:chat:readonly` | ให้เมนู "หา chat_id ของกลุ่ม" มองเห็นกลุ่ม |
   | `contact:user.id:readonly` | ส่งข้อความหาคนเป็นรายคนด้วย `lark_user_id` |

6. เมนู **Version Management & Release** → **สร้างเวอร์ชันแล้วขออนุมัติเผยแพร่**
   > **ข้อนี้ลืมกันบ่อยที่สุด** — ไม่เผยแพร่เวอร์ชัน สิทธิ์ที่เพิ่มไว้จะยังไม่มีผล
   > เรียก API แล้วจะได้ error ทั้งที่ตั้งค่าครบแล้ว

> `LARK_APP_SECRET` เป็นความลับ — อยู่ใน Script Properties เท่านั้น
> **ห้ามใส่ในโค้ด ห้ามขึ้น Git ห้ามส่งในแชท**

#### `LARK_GROUP_CHAT_ID` — ให้ระบบหาให้

ค่านี้หายากที่สุดเพราะไม่มีที่ไหนในหน้าจอ Lark แสดงตรง ๆ จึงทำเมนูช่วยไว้

1. **เชิญ bot เข้ากลุ่ม**ที่จะใช้แจ้งเตือนก่อน (ในกลุ่ม → เพิ่มสมาชิก → ค้นชื่อแอป)
2. ใส่ `LARK_APP_ID` กับ `LARK_APP_SECRET` ให้ครบก่อน
3. ในชีต กดเมนู **MGS Document Center → หา chat_id ของกลุ่ม Lark**
4. ระบบจะแสดงชื่อกลุ่มพร้อมค่าที่ขึ้นต้นด้วย `oc_` — คัดลอกของกลุ่มที่ต้องการมาใส่

ถ้าขึ้นว่า *ไม่พบกลุ่มที่ bot อยู่* แปลว่ายังไม่ได้เชิญ bot เข้ากลุ่ม
ถ้าขึ้น error เรื่องสิทธิ์ แปลว่ายังไม่ได้เผยแพร่เวอร์ชันในข้อ 6 ข้างบน

#### `WEBAPP_URL` — ได้หลัง deploy

ทำข้อ 2.5 ให้เสร็จก่อน แล้วคัดลอกลิงก์เว็บแอปกลับมาใส่ค่านี้
ใช้ทำลิงก์ในข้อความ Lark ให้กดจากมือถือเข้าใบงานได้เลย — ไม่ใส่ก็ใช้งานได้ แค่ไม่มีลิงก์ในข้อความ

**2.3 รันติดตั้ง**
กลับไปที่ Sheet → เมนู **MGS Document Center → ติดตั้งระบบ**
สร้างแท็บทั้งหมด · ใส่หัวคอลัมน์ · สร้างโฟลเดอร์ · ติดตั้งทริกเกอร์ (รันซ้ำได้ ข้อมูลไม่หาย)

**2.4 กรอกผู้ใช้** — ดูข้อ 3

**2.5 Deploy**
Deploy → New deployment → **Web app**
- Execute as: **Me**
- Who has access: **Anyone within <โดเมนบริษัท>**

แจก **ลิงก์เวอร์ชัน** ให้พนักงาน ห้ามแจกลิงก์ `/dev`
> แก้โค้ดแล้วต้อง **Deploy → Manage deployments → แก้เวอร์ชันเป็น New version** ทุกครั้ง
> ไม่งั้นผู้ใช้ยังเห็นของเก่า — นี่คือสาเหตุอันดับหนึ่งของ "แก้แล้วแต่ไม่เปลี่ยน"

## 3. สร้างผู้ใช้ของแต่ละแผนก

ตอนกดติดตั้ง ระบบเตรียมแท็บ **`Users`** ไว้ให้แล้ว พร้อมแถวของทั้ง 8 แผนก
หัวหน้าแต่ละแผนกกรอกทับแถวของตัวเองได้เลย

| คอลัมน์ | ต้องกรอก | ตัวอย่าง |
|---|---|---|
| `email` | ✔ | `somchai@mglobalsourcing.net` — ต้องเป็นอีเมลบริษัท |
| `full_name` | ✔ | `สมชาย ใจดี` |
| `dept` | ✔ | เลือกจากรายการ: `SR` `QC` `LS` `WH` `AC` `ACH` `GM` `IT` |
| `lark_user_id` | ควรมี | ไม่มีก็ใช้ได้ แต่จะได้แจ้งเตือนเฉพาะในกลุ่ม ไม่ได้ข้อความส่วนตัว |
| `manager_email` | | ใช้ตอนต้องส่งเรื่องขึ้นหัวหน้า |
| `is_active` | ✔ | `TRUE` / `FALSE` (คนลาออกให้เปลี่ยนเป็น FALSE **ห้ามลบแถว** — ประวัติจะอ้างไม่ถึง) |

เพิ่มทีละคนก็ได้: เมนู **เพิ่มผู้ใช้จากอีเมล...**
ตรวจว่าครบไหม: เมนู **ตรวจตารางผู้ใช้** — บอกทีละแผนกว่าใครยังไม่มี

**ความหมายของแผนก**

| รหัส | แผนก | เห็นยอดเงิน | หน้าที่พิเศษ |
|---|---|:---:|---|
| `SR` | จัดซื้อ | ✔ | ตั้งเรื่องขอจ่ายได้ |
| `QC` | QC | — | ตรวจรับ |
| `LS` | โลจิสติกส์ | — | จองรถ เปิดรหัสสินค้า |
| `WH` | คลังสินค้า | — | รับเข้าคลัง |
| `AC` | บัญชี | ✔ | ตั้งเรื่องขอจ่าย + บันทึกการจ่าย |
| `ACH` | หัวหน้าบัญชี | ✔ | **อนุมัติจ่าย** (ทุกยอด ไม่มีเกณฑ์วงเงิน) |
| `GM` | ผู้บริหาร | ✔ | อนุมัติ |
| `IT` | ผู้ดูแลระบบ | — | ตั้งค่าและดูแลผู้ใช้ · **ไม่อยู่ในสายอนุมัติ** |

> ผู้ดูแลระบบไม่เห็นยอดเงินและอนุมัติอะไรไม่ได้โดยตั้งใจ
> ผู้ดูแลที่อนุมัติเอกสารเองได้ ทำให้ระบบตรวจสอบเป็นแค่การตกแต่ง

## 4. นำข้อมูลเข้าจากไฟล์ Costing ของ SAP

### 4.1 เตรียมโฟลเดอร์ (ทำครั้งเดียว)

1. สร้างโฟลเดอร์ใน **Shared drive** เช่น `SAP-Costing`
2. เอาไอดีจาก URL ของโฟลเดอร์ ไปใส่ Script Property ชื่อ **`COSTING_FOLDER_ID`**

```
https://drive.google.com/drive/folders/1XyZ...
                                       └── ค่านี้คือ COSTING_FOLDER_ID ──┘
```

> **ต้องตั้งค่านี้ ระบบไม่ยอมเดาให้** — ถ้าไม่ระบุโฟลเดอร์ ระบบต้องค้นทั้งไดรฟ์
> แล้วอาจไปเจอไฟล์ชื่อเดียวกันที่ค้างอยู่ในโฟลเดอร์ดาวน์โหลดของใครสักคน
> แล้วเอาราคาเก่ามาตั้งเบิก — ยอมให้กดไม่ได้ดีกว่าหยิบไฟล์ผิดเงียบ ๆ

### 4.2 วางไฟล์

เอาไฟล์ที่ export จาก SAP มาวางในโฟลเดอร์นั้น **โดยใช้ชื่อเดิมทุกครั้ง**

| สายสินค้า | ชื่อไฟล์ที่ระบบมองหา |
|---|---|
| เครื่องจักร & โซลาร์ | `Costing Mech.xlsx` |
| อาหาร | `Costing Food.xlsx` |

- **ต้องเป็น `.xlsx` จริง ๆ** — ไฟล์ที่ export จาก SAP ใช้ได้เลย
  ถ้าเผลอเปิดแล้ว *บันทึกเป็น Google Sheets* ระบบจะหาไม่เจอ เพราะชื่อไม่มี `.xlsx` แล้ว
- **วางทับไฟล์เดิมได้เลย** ไม่ต้องลบของเก่า ไม่ต้องเปลี่ยนชื่อ ไม่ต้องใส่วันที่
- มีสายเดียวก็ได้ อีกสายที่ยังไม่มีไฟล์ระบบจะข้ามไป ไม่ทำให้ทั้งงานล้ม
- อยากเพิ่มสายใหม่: เพิ่มแถวใน `CFG.SOURCES` ที่ `SapCostingImport.gs`

### 4.3 กดนำเข้า

ที่ Sheet → เมนู **MGS Document Center**

| เมนู | ทำอะไร |
|---|---|
| **ตรวจไฟล์ต้นทางที่จะใช้** | บอกว่าเจอไฟล์ไหน แก้ล่าสุดเมื่อไหร่ — กดก่อนเสมอเพื่อยืนยันว่าไม่ได้หยิบไฟล์เก่า |
| **อ่านไฟล์ Costing (ดูผลก่อนนำเข้า)** | อ่านไฟล์ลงแท็บ `Staging` ให้ตรวจด้วยตา **ยังไม่สร้างรายการจริง** |
| **นำเข้ารายการใหม่จาก SAP Costing** | สร้างรายการใน `Deals` + งวดจ่ายใน `Payments` จริง |

**กติกาที่ระบบใช้ตอนอ่านไฟล์** (ตรงกับ `tools/costing-extract.py` ทุกข้อ)
1. อ่านเฉพาะชีตแรกของไฟล์
2. `PO Payment Term` ว่าง → `UNKNOWN` (ยังตั้งเบิกได้ แต่ติดธงว่าต้องยืนยันเงื่อนไข)
3. **ตัดแถวที่เงื่อนไขจ่ายมี LC ออก** — ธนาคารจ่ายตามเอกสาร ไม่ต้องตั้งเบิกในระบบนี้
4. ครบ 4 ฟิลด์ (`PO Number` · `Supplier` · `Price` · `Due Date`) → 🟢 · ไม่ครบ → 🔴 พร้อมบอกว่าขาดฟิลด์ไหน
5. ยอดที่อ่านเป็นตัวเลขไม่ได้ **ไม่ถูกตั้งเป็น 0** แต่ข้ามแถวนั้นแล้วรายงานให้เห็น

**กันนำเข้าซ้ำ** — ระบบจำด้วย *ลายนิ้วมือแถว* (สาย + PO + รายการ + ยอด + วันครบกำหนด)
ไม่ได้ใช้ลำดับแถว เพราะไฟล์รอบใหม่จาก SAP เรียงไม่เหมือนเดิม
วางไฟล์เดิมซ้ำสิบครั้งก็ได้รายการชุดเดียว

### 4.4 รายการใหม่เริ่มที่ขั้นไหน

เริ่มที่ขั้น **รับใบแจ้งหนี้ (ขั้นที่ 13)** โดยตั้งใจ — ไฟล์ Costing คือรายการที่ SAP ออก PO
ไปแล้วและกำลังรอจ่าย ไม่ใช่รายการที่เพิ่งเริ่มขอราคา ถ้าเริ่มที่ขั้นแรกจะกลายเป็นให้คน
เดินย้อนขั้นที่ทำไปแล้วในโลกจริง

### 4.5 เปิดให้แก้ไขทีละใบ

รายการที่นำเข้ามา **ยังแก้ไม่ได้** จนกว่าจะอยู่ในช่วงทดลอง —
เพิ่มเลขที่ต้องการลงแท็บ **`Pilot_Scope`** (คอลัมน์ `deal_no`)
นอกรายการนี้ระบบเปิดให้ดูอย่างเดียว ทำตามขั้นตอนเดิมไปก่อน

## 6. ดูแลประจำ

| เรื่อง | ดูที่ไหน |
|---|---|
| ระบบขัดข้อง | แท็บ `Errors` + อีเมลถึง `ADMIN_EMAIL` |
| แจ้งเตือนส่งไม่ออก | แท็บ `Notifications` คอลัมน์ `send_status` = `FAILED` |
| ใครทำอะไร | แท็บ `History` — **ห้ามลบ ห้ามแก้** |
| ความเห็นจากผู้ใช้ | แท็บ `Feedback` หรือหน้า "ความเห็นจากผู้ใช้" ในเว็บแอป |

**สำรองข้อมูล**: ไฟล์ → ดาวน์โหลด → xlsx ทุกสัปดาห์ระหว่างช่วงทดลอง
เก็บไว้นอกไดรฟ์เดียวกัน (Google เก็บ version history ให้ แต่ลบไฟล์ทั้งใบแล้วก็หายเหมือนกัน)

**ปิด Lark ชั่วคราว**: แท็บ `Config` → `LARK_ON` = `FALSE` (ใช้ตอนทดสอบ ไม่ให้กลุ่มโดนสแปม)

**ย้อนกลับเมื่อมีปัญหา**: Apps Script → Deploy → Manage deployments → เลือกเวอร์ชันก่อนหน้า
ข้อมูลในชีตไม่ถูกแตะ ย้อนแค่โค้ด
