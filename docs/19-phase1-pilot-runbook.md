# 19 — คู่มือติดตั้งและส่งมอบ Phase 1 (สำหรับ IT)

ระบบ **MGS Document Center** ช่วงทดลอง — ฐานข้อมูลเป็น Google Sheet · หน้าจอเป็น Apps Script Web App ·
แจ้งเตือนผ่าน Lark Bot API · ยังไม่เชื่อม API ของ SAP (Phase ถัดไป)

---

## 1. ของที่ต้องมีก่อนเริ่ม

| ของ | ใคร | หมายเหตุ |
|---|---|---|
| Google Workspace ของบริษัท | มีอยู่แล้ว | พนักงานทุกคนที่ร่วมทดลองต้องมีอีเมล `@mglobalsourcing.net` |
| Shared drive สำหรับเก็บเอกสาร | IT | อย่าใช้ My Drive ของคนใดคนหนึ่ง — คนนั้นลาออกแล้วไฟล์หายไปด้วย |
| Lark app (bot) | IT + Lark admin | ต้องได้ `app_id`, `app_secret` และเปิดสิทธิ์ส่งข้อความ |
| `chat_id` ของกลุ่มแจ้งเตือน | IT | เชิญ bot เข้ากลุ่มก่อน แล้วจึงอ่าน chat_id ได้ |

## 2. ติดตั้ง (ครั้งเดียว ~30 นาที)

**2.1 สร้างไฟล์**

1. สร้าง Google Sheet ใหม่ใน **Shared drive** (ไม่ใช่ My Drive ของใครคนหนึ่ง)
   ตั้งชื่อ `MGS Document Center — ฐานข้อมูล`
2. เมนู **ส่วนขยาย → Apps Script** — จะได้โปรเจกต์สคริปต์ที่ผูกกับ Sheet ใบนี้
3. เอาโค้ดเข้าโปรเจกต์ ด้วยวิธี **A** หรือ **B**

#### วิธี A — คัดลอกวาง (ไม่ต้องติดตั้งอะไร · แนะนำสำหรับครั้งแรก)

1. ในตัวแก้ไข จะมีไฟล์ `Code.gs` เปล่าอยู่แล้ว — เปิดไว้ก่อน ค่อยวางทับตอนถึงคิว
2. ไฟล์ `.gs` แต่ละไฟล์: กด **+ ข้าง Files → Script**
   แล้วตั้งชื่อ **ไม่ต้องพิมพ์ `.gs`** (พิมพ์ `Flow` ระบบเติม `.gs` ให้เอง)
3. `index.html`: กด **+ → HTML** แล้วตั้งชื่อ **`index`** — ห้ามพิมพ์ `.html`
   > ชื่อต้องเป็น `index` เป๊ะ ๆ เพราะ `Code.gs` เรียก `createTemplateFromFile('index')`
   > ตั้งชื่ออื่นแล้วจะเปิดเว็บแอปไม่ขึ้น ฟ้องว่าหาไฟล์ไม่เจอ
4. `appsscript.json`: **สร้างใหม่ไม่ได้และไม่ต้องสร้าง** — ไฟล์นี้มีอยู่แล้วทุกโปรเจกต์ แค่ถูกซ่อนไว้
   ทำให้มันโผล่มาแล้ววางทับ (รายละเอียดข้างล่าง)

##### วาง `appsscript.json` ยังไง

ปุ่ม **+** ในตัวแก้ไขสร้างได้แค่ Script / HTML เท่านั้น ไม่มีตัวเลือก JSON —
เพราะไฟล์นี้เป็นของโปรเจกต์อยู่แล้ว หน้าที่เราคือ**เปิดให้เห็นแล้วแก้เนื้อหา**

1. กด **⚙ Project Settings** (รูปเฟือง แถบซ้าย)
2. ติ๊ก **"Show 'appsscript.json' manifest file in editor"**
3. กลับไปแถบ **Editor** (`< >`) — จะเห็น `appsscript.json` โผล่ในรายการไฟล์
4. คลิกเปิด **ลบเนื้อหาเดิมทั้งหมด** แล้ววางของเราทับ → **Save**

**ห้ามเปลี่ยนชื่อไฟล์** และ **ต้องเป็น JSON ที่ถูกต้อง** — พิมพ์ตกจุลภาคแล้วจะ Save ไม่ผ่าน
ตัวแก้ไขจะฟ้องตรงบรรทัดที่ผิด

**เนื้อหาแต่ละบรรทัดมีผลจริง**

| ค่า | ทำอะไร | ถ้าไม่ใส่ |
|---|---|---|
| `timeZone: Asia/Bangkok` | เวลาที่บันทึกใน History และวันครบกำหนด | เวลาเพี้ยนไป 7 ชม. วันครบกำหนดคลาดไปหนึ่งวัน |
| `runtimeVersion: V8` | ใช้ JavaScript รุ่นใหม่ | โค้ดรันไม่ได้ (โปรเจกต์ใหม่เป็น V8 อยู่แล้ว) |
| `oauthScopes` (6 ตัว) | สิทธิ์ที่ระบบขอจากผู้ใช้ | ระบบขอสิทธิ์กว้างเกินจำเป็น |
| `webapp` | ตั้งค่าเว็บแอปตอน deploy ด้วย clasp | ถ้า deploy จากหน้าจอ เลือกในกล่อง deploy แทนได้ |

`oauthScopes` ทั้ง 6 ตัวตรงกับของที่โค้ดเรียกใช้จริง ไม่มีเกิน

| scope | เพราะโค้ดใช้ |
|---|---|
| `spreadsheets` | `SpreadsheetApp` — ฐานข้อมูล |
| `drive` | `DriveApp` — เก็บเอกสารแนบ |
| `script.external_request` | `UrlFetchApp` — ยิง Lark |
| `script.scriptapp` | `ScriptApp` — ติดตั้งทริกเกอร์ |
| `userinfo.email` | `Session.getActiveUser()` — รู้ว่าใครล็อกอิน |
| `script.send_mail` | `MailApp` — อีเมลแจ้ง IT เมื่อระบบขัดข้อง |

> **หลังแก้ `oauthScopes` ระบบจะขอสิทธิ์ใหม่อีกรอบ** ตอนรันครั้งถัดไป — เป็นเรื่องปกติ กด Allow

**ถ้าไม่อยากแตะไฟล์นี้เลยก็ได้** — Apps Script เดาสิทธิ์จากโค้ดให้เอง แต่ต้องทำสองอย่างแทน
1. ตั้ง timezone เป็น `(GMT+07:00) Bangkok` ใน **Project Settings**
2. ตอน deploy เลือก *Execute as: Me* และ *Who has access: ทุกคนในโดเมน* ในกล่อง deploy

ผลลัพธ์ใช้งานได้เหมือนกัน ต่างแค่ระบบจะขอสิทธิ์กว้างกว่าที่จำเป็น

#### วิธี B — clasp (สำหรับ IT ที่จะอัปเดตโค้ดบ่อย)

**ก่อนอื่น** เปิด Apps Script API ที่ <https://script.google.com/home/usersettings>
(ปิดอยู่โดยค่าเริ่มต้น — ไม่เปิดแล้ว `clasp push` จะขึ้น `User has not enabled the Apps Script API`)

```bash
npm i -g @google/clasp
clasp login                      # ล็อกอินด้วยบัญชีบริษัท

# ใช้ clone ไม่ใช่ create เพราะสร้าง Sheet ไปแล้วในข้อ 1
# หา Script ID จาก ตัวแก้ไข → ⚙ Project Settings → Script ID
cd apps-script
clasp clone <SCRIPT_ID>
clasp push
```

> **อย่าใช้ `clasp create --type sheets`** — คำสั่งนั้นสร้าง Sheet **ใบใหม่**
> จะได้ไฟล์สองใบและโค้ดไปเกาะใบที่ผิด
>
> `clasp clone` จะดึง `appsscript.json` ของโปรเจกต์เปล่ามาทับของเรา
> หลัง clone ให้ `git checkout appsscript.json` เพื่อเอาของเรากลับมา แล้วค่อย `clasp push`
>
> `clasp clone` สร้าง `.clasp.json` ซึ่ง `.gitignore` กันไว้แล้ว — เป็นค่าเฉพาะเครื่อง ไม่ต้องขึ้น Git

**ตรวจว่าเข้าครบ**: ในตัวแก้ไขต้องเห็น **10 ไฟล์ `.gs` + `index.html` + `appsscript.json`**
แล้วกด **Save** หนึ่งครั้ง — ถ้ามีวงเล็บหรือเครื่องหมายคำพูดขาด ตัวแก้ไขจะขีดเส้นแดงให้เห็นทันที

**2.2 ตั้ง Script Properties** (ตัวแก้ไข Apps Script → ⚙ Project Settings → เลื่อนลงล่างสุด → **Script Properties → Add script property**)

|---|---|:--:|
| `SPREADSHEET_ID` | **ไม่ต้องกรอก** — ระบบเติมให้เองตอนกดเมนูติดตั้ง | — |
| `DRIVE_ROOT_ID` | สร้างโฟลเดอร์ใน Shared drive แล้วเปิดดู · เอาจาก URL | ✔ |
| `ADMIN_EMAIL` | อีเมลของ IT ที่จะรับแจ้งเมื่อระบบขัดข้อง — เลือกเอง | ✔ |
| `LARK_APP_ID` · `LARK_APP_SECRET` | Lark Developer Console → แอปของคุณ → Credentials & Basic Info | ✔ |
| `LARK_GROUP_CHAT_ID` | **กดเมนู "หา chat_id ของกลุ่ม Lark"** ในชีต | ✔ |

#### `DRIVE_ROOT_ID` — เอาจาก URL ของโฟลเดอร์

1. เปิด Google Drive → **Shared drives** → สร้างโฟลเดอร์ `MGS-Documents`
2. เปิดโฟลเดอร์นั้น แล้วดูที่ URL

```
https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz012345
                                       └────────── ค่านี้คือ DRIVE_ROOT_ID ──────────┘
```

> **ต้องตั้งค่านี้ก่อนกดเมนูติดตั้ง** — ถ้ายังไม่ตั้ง ระบบจะสร้างโฟลเดอร์ให้เองแต่ไปอยู่ใน
> **"ไดรฟ์ของฉัน" ของคนที่กดติดตั้ง** แปลว่าเอกสารของทั้งบริษัทไปอยู่ในไดรฟ์ส่วนตัวคนเดียว
> วันที่คนนั้นลาออกแล้วบัญชีถูกปิด ไฟล์หายไปพร้อมกัน
> (ระบบจะเตือนบนหน้าจอถ้าเกิดกรณีนี้ — ย้ายโฟลเดอร์ไป Shared drive แล้วแก้ค่าให้ตรงได้)

`SPREADSHEET_ID` ถ้าอยากดูเองก็อยู่ใน URL ของ Sheet ที่เดียวกัน:
`https://docs.google.com/spreadsheets/d/`**`<SPREADSHEET_ID>`**`/edit`

#### `LARK_APP_ID` · `LARK_APP_SECRET` — จาก Lark Developer Console

1. เข้า <https://open.larksuite.com/app> (หรือ <https://open.feishu.cn/app> ถ้าใช้ Feishu)
   ด้วยบัญชีที่มีสิทธิ์สร้างแอป — ถ้าเข้าไม่ได้ต้องให้ **Lark admin** ทำให้
2. **Create custom app** → ตั้งชื่อ เช่น `MGS Document Center`
3. เมนู **Credentials & Basic Info** → คัดลอก **App ID** และ **App Secret**
4. เมนู **Features → Bot** → เปิดใช้งาน (ไม่เปิด bot จะส่งข้อความไม่ได้)
5. เมนู **Permissions & Scopes** → เพิ่มสิทธิ์

   | สิทธิ์ | ใช้ทำอะไร |
   |---|---|
   | `im:message:send_as_bot` | ส่งข้อความในนาม bot |
   | `im:chat:readonly` | ให้เมนู "หา chat_id ของกลุ่ม" มองเห็นกลุ่ม |
   | `contact:user.id:readonly` | ส่งข้อความหาคนเป็นรายคนด้วย `lark_user_id` |

6. เมนู **Version Management & Release** → **สร้างเวอร์ชันแล้วขออนุมัติเผยแพร่**
   > **ข้อนี้ลืมกันบ่อยที่สุด** — ไม่เผยแพร่เวอร์ชัน สิทธิ์ที่เพิ่มไว้จะยังไม่มีผล
   > เรียก API แล้วจะได้ error ทั้งที่ตั้งค่าครบแล้ว

> `LARK_APP_SECRET` เป็นความลับ — อยู่ใน Script Properties เท่านั้น
> **ห้ามใส่ในโค้ด ห้ามขึ้น Git ห้ามส่งในแชท**

#### `LARK_GROUP_CHAT_ID` — ให้ระบบหาให้

ค่านี้หายากที่สุดเพราะไม่มีที่ไหนในหน้าจอ Lark แสดงตรง ๆ จึงทำเมนูช่วยไว้

1. **เชิญ bot เข้ากลุ่ม**ที่จะใช้แจ้งเตือนก่อน (ในกลุ่ม → เพิ่มสมาชิก → ค้นชื่อแอป)
2. ใส่ `LARK_APP_ID` กับ `LARK_APP_SECRET` ให้ครบก่อน
3. ในชีต กดเมนู **MGS Document Center → หา chat_id ของกลุ่ม Lark**
4. ระบบจะแสดงชื่อกลุ่มพร้อมค่าที่ขึ้นต้นด้วย `oc_` — คัดลอกของกลุ่มที่ต้องการมาใส่

ถ้าขึ้นว่า *ไม่พบกลุ่มที่ bot อยู่* แปลว่ายังไม่ได้เชิญ bot เข้ากลุ่ม
ถ้าขึ้น error เรื่องสิทธิ์ แปลว่ายังไม่ได้เผยแพร่เวอร์ชันในข้อ 6 ข้างบน

#### `WEBAPP_URL` — ได้หลัง deploy

ทำข้อ 2.5 ให้เสร็จก่อน แล้วคัดลอกลิงก์เว็บแอปกลับมาใส่ค่านี้
ใช้ทำลิงก์ในข้อความ Lark ให้กดจากมือถือเข้าใบงานได้เลย — ไม่ใส่ก็ใช้งานได้ แค่ไม่มีลิงก์ในข้อความ

**2.3 รันติดตั้ง**
กลับไปที่ Sheet → เมนู **MGS Document Center → ติดตั้งระบบ**
สร้างแท็บทั้งหมด · ใส่หัวคอลัมน์ · สร้างโฟลเดอร์ · ติดตั้งทริกเกอร์ (รันซ้ำได้ ข้อมูลไม่หาย)

**2.4 กรอกผู้ใช้** — ดูข้อ 3

**2.5 Deploy**
Deploy → New deployment → **Web app**
- Execute as: **Me**
- Who has access: **Anyone within <โดเมนบริษัท>**

แจก **ลิงก์เวอร์ชัน** ให้พนักงาน ห้ามแจกลิงก์ `/dev`
> แก้โค้ดแล้วต้อง **Deploy → Manage deployments → แก้เวอร์ชันเป็น New version** ทุกครั้ง
> ไม่งั้นผู้ใช้ยังเห็นของเก่า — นี่คือสาเหตุอันดับหนึ่งของ "แก้แล้วแต่ไม่เปลี่ยน"

## 3. สร้างผู้ใช้ของแต่ละแผนก

ตอนกดติดตั้ง ระบบเตรียมแท็บ **`Users`** ไว้ให้แล้ว พร้อมแถวของทุกแผนกและทุกทีมย่อย
หัวหน้าแต่ละแผนกกรอกทับแถวของตัวเองได้เลย

| คอลัมน์ | ต้องกรอก | ตัวอย่าง |
|---|---|---|
| `email` | ✔ | `somchai@mglobalsourcing.net` — ต้องเป็นอีเมลบริษัท |
| `full_name` | ✔ | `สมชาย ใจดี` |
| `dept` | ✔ | เลือกจากรายการในช่อง — ใช้**ทีมย่อย** (`SR_FD` `SR_MC` `AC_FN` `AC_TH`) เป็นหลัก |
| `lark_user_id` | ควรมี | ไม่มีก็ใช้ได้ แต่จะได้แจ้งเตือนเฉพาะในกลุ่ม ไม่ได้ข้อความส่วนตัว |
| `manager_email` | | ใช้ตอนต้องส่งเรื่องขึ้นหัวหน้า |
| `is_active` | ✔ | `TRUE` / `FALSE` (คนลาออกให้เปลี่ยนเป็น FALSE **ห้ามลบแถว** — ประวัติจะอ้างไม่ถึง) |

เพิ่มทีละคนก็ได้: เมนู **เพิ่มผู้ใช้จากอีเมล...**
ตรวจว่าครบไหม: เมนู **ตรวจตารางผู้ใช้** — บอกทีละแผนกว่าใครยังไม่มี

**ความหมายของแผนก**

| รหัส | แผนก | เห็นยอดเงิน | หน้าที่พิเศษ |
|---|---|:---:|---|
| `QC` | QC | — | ตรวจรับ |
| `LS` | โลจิสติกส์ | — | จองรถ เปิดรหัสสินค้า |
| `WH` | คลังสินค้า | — | รับเข้าคลัง |
| `ACH` | หัวหน้าบัญชี | ✔ | **อนุมัติจ่าย** (ทุกยอด ไม่มีเกณฑ์วงเงิน) |
| `GM` | ผู้บริหาร | ✔ | อนุมัติ |
| `IT` | ผู้ดูแลระบบ | — | ตั้งค่าและดูแลผู้ใช้ · **ไม่อยู่ในสายอนุมัติ** |

### สองแผนกที่แยกเป็นทีมย่อย

จัดซื้อกับบัญชีทำงานกันคนละคนอยู่แล้วในชีวิตจริง ระบบจึงแยกให้ตรงกับของจริง
**ระบบเลือกทีมให้เอง** จากตัวใบ ไม่ต้องมีใครมานั่งแจกงาน

| รหัส | แผนก | เห็นยอดเงิน | รับใบที่ | ตัดสินจาก |
|---|---|:---:|---|---|
| `SR_FD` | จัดซื้ออาหาร | ✔ | สายอาหาร (`PO-F…`) | เลข PO จาก SAP |
| `SR_MC` | จัดซื้อเครื่องจักร | ✔ | สายเครื่องจักร & โซลาร์ (`PO-M…`) | เลข PO จาก SAP |
| `SR` | จัดซื้อ (ดูแทนได้ทั้งสองสาย) | ✔ | **ทั้งสองสาย** + รายการค่าใช้จ่าย (`PO-O…`) | — |
| `AC_FN` | บัญชีต่างประเทศ | ✔ | สกุลเงินอื่นที่ไม่ใช่ THB (USD · EUR · CNY …) | สกุลเงินของใบ |
| `AC_TH` | บัญชีในประเทศ | ✔ | THB หรือไม่ระบุสกุลเงิน | สกุลเงินของใบ |
| `AC` | บัญชี (ดูแทนได้ทั้งสองฝั่ง) | ✔ | **ทั้งสองฝั่ง** | — |

**กรอกยังไง** — ตั้งคนส่วนใหญ่เป็น**ทีมย่อย** (`SR_FD` `SR_MC` `AC_FN` `AC_TH`)
เก็บ `SR` กับ `AC` เฉย ๆ ไว้ให้เฉพาะ**หัวหน้างานที่ต้องทำแทนได้ทั้งสองทีม** เช่นวันที่ลูกทีมลา
ไม่มีคนในแถว `SR`/`AC` ก็ใช้งานได้ปกติ ตราบใดที่ทีมย่อยมีคนครบ

> คนที่ตั้งเป็น `AC_TH` จะเปิดใบสกุล USD ไม่ได้ ระบบจะบอกว่าใบนี้เป็นของบัญชีต่างประเทศ
> เช่นเดียวกับ `SR_FD` ที่แตะใบสายเครื่องจักรไม่ได้ — **นี่คือจุดประสงค์ของการแยก**
> ถ้าอยากให้ใครทำได้ทั้งคู่ ให้ตั้งเป็น `AC` หรือ `SR` เฉย ๆ
>
> เพิ่มสกุลเงินที่ถือว่าเป็นในประเทศ: แก้ `LOCAL_CCY` ใน `Flow.gs`
> เปลี่ยนว่าสายสินค้าไหนเป็นของทีมไหน: แก้ `MOD_SR` ใน `Flow.gs`

## 3.1 เจ้าของงานรายใบ — แท็บ `Assignments`

ตอนติดตั้ง ระบบสร้างแท็บ **`Assignments`** พร้อมแถวของทุกกลุ่มสินค้าไว้ให้
หัวหน้าจัดซื้อกรอกอีเมลของคนที่ดูแลแต่ละกลุ่ม

| คอลัมน์ | ตัวอย่าง |
|---|---|
| `group_code` | `FOOD` · `MECH` · `OTHER` (ระบบเติมให้แล้ว) |
| `group_name` | ชื่อกลุ่มภาษาไทย (ระบบเติมให้แล้ว) |
| `sr_email` | อีเมลจัดซื้อที่ดูแลกลุ่มนี้ |

**มีผลยังไง**
- ตอนนำเข้าจาก Costing ระบบใส่ `owner_email` ให้ทุกใบตามกลุ่มของใบนั้น
- แจ้งเตือนเมื่อถึงคิว **ส่งหาเจ้าของคนเดียว** ไม่ยิงทั้งแผนก คนอื่นจะได้ไม่ต้องอ่านงานที่ไม่ใช่ของตัวเอง
- **เว้นว่างได้** — ระบบจะแจ้งทั้งแผนกแทน และตอนนำเข้าจะบอกว่ากลุ่มไหนยังไม่มีเจ้าของกี่ใบ

> กลุ่มมาจากเลขหน้า PO (`PO-F…` = อาหาร · `PO-M…` = เครื่องจักร · `PO-O…` = ค่าใช้จ่ายอื่น)
> ซึ่งมาจาก SAP โดยตรง ไม่ใช่ค่าที่คนพิมพ์

> ผู้ดูแลระบบไม่เห็นยอดเงินและอนุมัติอะไรไม่ได้โดยตั้งใจ
> ผู้ดูแลที่อนุมัติเอกสารเองได้ ทำให้ระบบตรวจสอบเป็นแค่การตกแต่ง

## 3.2 สายอนุมัติจ่าย — สี่มือ

| ลำดับ | ใคร | ทำอะไร | ทำอะไรไม่ได้ |
|---|---|---|---|
| 1 | **จัดซื้อ** (ทีมตามสายสินค้า) | ตั้งเรื่องขอทำจ่าย แนบเลขเอกสารเรียกเก็บของงวดนั้น | ตรวจหรืออนุมัติของตัวเอง |
| 2 | **บัญชี** (ฝั่งตามสกุลเงิน) | **ตรวจเอกสาร** → ผ่าน หรือ **ตีกลับพร้อมเหตุผล** | ตรวจใบที่ตัวเองตั้งเรื่อง |
| 3 | **หัวหน้าบัญชี** | อนุมัติ หรือตีกลับ | อนุมัติใบที่ตัวเองตั้งเรื่องหรือตรวจ |
| 4 | **บัญชี** | บันทึกการจ่าย + แนบสลิป | บันทึกใบที่ตัวเองอนุมัติ |

```
รอตั้งเรื่อง → รอบัญชีตรวจสอบ → บัญชีตรวจแล้ว รออนุมัติ → อนุมัติแล้ว รอทำจ่าย → จ่ายแล้ว
                     ↓ ตีกลับ            ↓ ตีกลับ
                        ตีกลับให้แก้ไข → จัดซื้อแก้แล้วส่งใหม่ (ใช้เลขคำขอเดิม)
```

**การตีกลับ**
- **บังคับเขียนเหตุผล** อย่างน้อย 5 ตัวอักษร — ตีกลับเฉย ๆ ทำให้ผู้ขอต้องเดาว่าต้องแก้อะไร
  แล้วก็จะกลับไปถามกันในไลน์ ซึ่งคือปัญหาที่ระบบนี้ตั้งใจแก้
- **แจ้งเตือนถึงผู้ขอทันที** ทาง Lark พร้อมเหตุผล และแจ้งจัดซื้อคนอื่นด้วยเผื่อผู้ขอลา
- เหตุผลติดอยู่กับงวดนั้นถาวร ดูได้ในหน้าใบและในแท็บ `History`
- ส่งใหม่ได้จากใบเดิม **ใช้เลขคำขอเดิม** จะได้ตามเรื่องเดียวกันต่อ ไม่ใช่เรื่องใหม่
- ส่งใหม่แล้วต้องให้บัญชีตรวจใหม่เสมอ (ล้างผลตรวจเดิมทิ้ง)

**ตีกลับได้ทั้งสองด่าน** — ทั้งบัญชีตอนตรวจ และหัวหน้าบัญชีตอนอนุมัติ
ด่านที่ปฏิเสธไม่ได้ ไม่ใช่ด่านตรวจ

## 3.3 เพดานยอดจ่าย — สิ่งที่ระบบไม่ยอมให้ผ่านตั้งแต่แรก

คนตรวจสี่มือช่วยได้เมื่อมีคนอ่านเจอ แต่ยอดที่พิมพ์เลขศูนย์เกินมาตัวเดียวมักผ่านสายตาไปได้
สี่ข้อนี้ระบบกันที่เซิร์ฟเวอร์ตอนกด **ตั้งเรื่อง** ไม่ใช่ตอนตรวจ

| กัน | เงื่อนไข | ข้อความที่ผู้ใช้เห็น |
|---|---|---|
| ใบเรียกเก็บซ้ำ | เลขเอกสารเดิมถูกใช้ตั้งเบิกงวดอื่นของใบนี้แล้ว (ที่ไม่ถูกยกเลิก) | บอกว่าไปซ้ำกับงวดที่เท่าไหร่ |
| เกินยอดคงเหลือ | ยอดที่ขอ > ยอดใบ − งวดอื่นที่ยังมีผล | บอกยอดคงเหลือจริง |
| เกินยอดในเอกสาร | ยอดที่ขอ > ยอดในใบเรียกเก็บที่แนบ | บอกยอดในเอกสาร |
| งวด LC | งวดที่ธนาคารจ่ายตามเอกสาร | ตั้งเบิกในระบบนี้ไม่ได้เลย |

**ตรวจใบซ้ำก่อนตรวจยอดเสมอ** — ใบที่หยิบซ้ำมักทำให้ยอดคงเหลือหมดไปด้วย
ถ้าระบบตอบว่า "เกินยอดคงเหลือ" คนกรอกจะไปลดยอดลง แทนที่จะรู้ว่าหยิบเอกสารผิดใบ

ยอดคงเหลือ **ไม่นับ** งวดที่ยกเลิก ถูกตีกลับ หรือยังไม่ได้ตั้งเรื่อง — เพราะเงินก้อนนั้นยังไม่ถูกกัน

## 3.35 PO ที่มีสินค้าหลายรายการ

ไฟล์ Costing จาก SAP ส่งมา **บรรทัดละรายการสินค้า** PO ใบเดียวจึงมีได้หลายบรรทัด

| เรื่อง | ระบบทำอย่างไร |
|---|---|
| นำเข้า | รวมทุกบรรทัดของ PO เดียวกันเป็น **1 ใบ** · ยอดของใบ = **ผลรวมทุกบรรทัด** |
| รายการย่อย | เก็บครบทุกบรรทัดในแท็บ **`Deal_Items`** (ชื่อสินค้า · จำนวน · ราคาต่อรายการ) |
| หัวใบ | เขียนว่า *"<สินค้าแรก> และอีก N รายการ"* — ไม่ใช่โชว์แค่รายการแรกเหมือนไม่มีอย่างอื่น |
| หน้าสรุปหลังนำเข้า | บอกว่าใบไหนมีกี่รายการ ยอดรวมเท่าไหร่ |

**คลังกรอกอะไร** — ทีมเลือกให้ **แนบใบรับสินค้า (GRPO) อย่างเดียว** ไม่ต้องกรอกจำนวนทีละรายการ
ช่อง *"จำนวนที่รับเข้าคลังจริง"* จึง**ไม่บังคับ**สำหรับใบหลายรายการ (ยังกรอกได้ถ้าอยาก)
เพราะจำนวนของแต่ละรายการอยู่คนละหน่วย (4 SET + 20 SET + 500 M) บวกเป็นเลขเดียวไม่ได้

**สิ่งที่แลกไป และระบบชดเชยอย่างไร**

ระบบ**เทียบขาด/เกินให้ไม่ได้**สำหรับใบหลายรายการ — ด่านอัตโนมัติในข้อ 3.4 ใช้ไม่ได้กับใบพวกนี้
ถ้าปล่อยไว้เฉย ๆ ใบหลายรายการจะปิดได้โดยไม่มีใครตรวจเลย ซึ่งหลวมกว่าใบรายการเดียว
จึงเปลี่ยนจาก **"ระบบตรวจให้"** เป็น **"คนตรวจแล้วเซ็นรับ"**:

> ตอนปิดใบ ระบบจะไม่ยอมให้ปิดจนกว่าบัญชีจะเปิดใบรับสินค้าที่คลังแนบไว้
> เทียบกับใบแจ้งหนี้ทีละรายการ แล้ว**กดยืนยันพร้อมเขียนว่าตรวจแล้วผลเป็นอย่างไร**
> ชื่อผู้ตรวจ เวลา และข้อความ ถูกเก็บถาวรและแจ้งเข้ากลุ่ม Lark เหมือนกรณีรับของขาด

ผลคือ **ทุกใบมีชื่อผู้รับผิดชอบติดอยู่เสมอ** ไม่ว่าระบบจะนับให้ได้หรือนับไม่ได้

> ถ้าภายหลังอยากให้ระบบเทียบจำนวนให้อัตโนมัติ ต้องให้คลังกรอกจำนวนทีละรายการ
> โครงข้อมูลรองรับไว้แล้ว (`Deal_Items.qty_in`) เปิดใช้ได้โดยไม่ต้องรื้อของเดิม

## 3.4 รับของไม่ครบ — ปิดใบได้ แต่ต้องมีคนเซ็นรับ

ฝั่ง Food รับของ **เกินหรือขาดจากใบสั่งได้เป็นเรื่องปกติ** (ของสด ชั่งจริงไม่เท่าที่สั่ง)
ระบบจึงไม่ห้ามรับไม่เท่า แต่ต้องไม่ปล่อยให้ปิดใบเงียบ ๆ ราวกับรับครบ

- ทุกใบเทียบ **จำนวนที่รับเข้าคลัง** กับ **จำนวนในใบแจ้งหนี้** อ่านหน่วยได้ (`500 KG` · `1,200.5 kg`)
- ต่างกันเมื่อไหร่ หน้าใบขึ้นแถบเตือนบอก *ขาด/เกินเท่าไหร่ กี่เปอร์เซ็นต์* ทั้งสองทาง
- ถ้า **รับขาด** ระบบ **ปิดใบไม่ได้** ที่ขั้นตรวจ 3 ทาง จนกว่าจะมีคนกด **ยืนยันจบ PO ทั้งที่รับไม่ครบ**
  พร้อม**เขียนเหตุผล** (อย่างน้อย 5 ตัวอักษร) — เช่น ผู้ขายส่งได้เท่านี้ · ตัดยอดส่วนที่เหลือแล้ว
- การกดยืนยันเก็บ **ชื่อผู้กด · เวลา · เหตุผล · จำนวนที่ขาด** และแจ้งเข้ากลุ่ม Lark
- รับ**เกิน**ไม่บล็อกการปิดใบ แต่ยังเตือนบนหน้าใบ เพราะจ่ายเกินใบสั่งเป็นเรื่องที่บัญชีต้องเห็น

```
https://drive.google.com/drive/folders/1XyZ...
                                       └── ค่านี้คือ COSTING_FOLDER_ID ──┘
```

### 4.2 วางไฟล์

เอาไฟล์ที่ export จาก SAP มาวางในโฟลเดอร์นั้น **โดยใช้ชื่อเดิมทุกครั้ง**

  ถ้าเผลอเปิดแล้ว *บันทึกเป็น Google Sheets* ระบบจะหาไม่เจอ เพราะชื่อไม่มี `.xlsx` แล้ว
- **วางทับไฟล์เดิมได้เลย** ไม่ต้องลบของเก่า ไม่ต้องเปลี่ยนชื่อ ไม่ต้องใส่วันที่
- มีสายเดียวก็ได้ อีกสายที่ยังไม่มีไฟล์ระบบจะข้ามไป ไม่ทำให้ทั้งงานล้ม
- อยากเพิ่มสายใหม่: เพิ่มแถวใน `CFG.SOURCES` ที่ `SapCostingImport.gs`

### 4.3 กดนำเข้า

ที่ Sheet → เมนู **MGS Document Center**

| เมนู | ทำอะไร |
|---|---|
| **ตรวจไฟล์ต้นทางที่จะใช้** | บอกว่าเจอไฟล์ไหน แก้ล่าสุดเมื่อไหร่ — กดก่อนเสมอเพื่อยืนยันว่าไม่ได้หยิบไฟล์เก่า |
| **อ่านไฟล์ Costing (ดูผลก่อนนำเข้า)** | อ่านไฟล์ลงแท็บ `Staging` ให้ตรวจด้วยตา **ยังไม่สร้างรายการจริง** |
| **นำเข้ารายการใหม่จาก SAP Costing** | สร้างรายการใน `Deals` + งวดจ่ายใน `Payments` จริง |

**กติกาที่ระบบใช้ตอนอ่านไฟล์** (ตรงกับ `tools/costing-extract.py` ทุกข้อ)
1. อ่านเฉพาะชีตแรกของไฟล์
2. `PO Payment Term` ว่าง → `UNKNOWN` (ยังตั้งเบิกได้ แต่ติดธงว่าต้องยืนยันเงื่อนไข)
3. **ตัดแถวที่เงื่อนไขจ่ายมี LC ออก** — ธนาคารจ่ายตามเอกสาร ไม่ต้องตั้งเบิกในระบบนี้
4. ครบ 4 ฟิลด์ (`PO Number` · `Supplier` · `Price` · `Due Date`) → 🟢 · ไม่ครบ → 🔴 พร้อมบอกว่าขาดฟิลด์ไหน
5. ยอดที่อ่านเป็นตัวเลขไม่ได้ **ไม่ถูกตั้งเป็น 0** แต่ข้ามแถวนั้นแล้วรายงานให้เห็น

**กันนำเข้าซ้ำ** — ระบบจำด้วย *ลายนิ้วมือแถว* (สาย + PO + รายการ + ยอด + วันครบกำหนด)
ไม่ได้ใช้ลำดับแถว เพราะไฟล์รอบใหม่จาก SAP เรียงไม่เหมือนเดิม
วางไฟล์เดิมซ้ำสิบครั้งก็ได้รายการชุดเดียว

### 4.4 รายการใหม่เริ่มที่ขั้นไหน

เริ่มที่ขั้น **ผู้ขายเซ็น PO กลับ (ขั้นที่ 9 · เจ้าของคือจัดซื้อ)** โดยตั้งใจ — ไฟล์ Costing คือรายการ
ที่ SAP ออก PO ไปแล้ว ไม่ใช่รายการที่เพิ่งเริ่มขอราคา ถ้าเริ่มที่ขั้นแรกจะกลายเป็นให้คนเดิน
ย้อนขั้นที่ทำไปแล้วในโลกจริง แต่จะเริ่มหลังจากนี้ก็ไม่ได้ เพราะ**จัดซื้อต้องแนบ PO ก่อน**
ทั้งสายถึงจะมีเอกสารตั้งต้นให้ตรวจ

ขั้นที่ถูกข้ามไป (1–8) ระบบบันทึกไว้ว่า *ข้ามเพราะนำเข้าจาก SAP* พร้อมรายชื่อเอกสารที่ยังไม่มี
ไม่ได้ทำเป็นเหมือนทำครบแล้ว — เปิดดูได้ในประวัติของรายการนั้น

ค่านี้แก้ได้ที่แท็บ `Config` คีย์ `IMPORT_START_STAGE` (นับจาก 0 → ค่าเริ่มต้น `8`)

### 4.4.1 PO ที่ดำเนินการไปแล้ว ไม่กลับมาขึ้นซ้ำ

ไฟล์ Costing รอบใหม่จาก SAP ยังมี PO เดิมติดมาด้วยเสมอ ระบบกันซ้ำสองชั้น

| ชั้น | ดูจาก | ผลลัพธ์ |
|---|---|---|
| 1 | **เลขที่รายการ** (`deal_no`) | มีอยู่แล้ว → ข้าม ไม่สร้างใหม่ ไม่ทับของเดิม |
| 2 | **ลายนิ้วมือแถว** (สาย + PO + รายการ + ยอด + วันครบกำหนด) | ซ้ำ → ข้าม |

ชั้นที่ 1 สำคัญกว่า เพราะรายการที่เดินไปแล้วยอดอาจถูกแก้ในไฟล์ ลายนิ้วมือจะไม่ตรง
แต่มันคือ PO ใบเดิม — ถ้าดูแค่ลายนิ้วมือจะได้รายการซ้อนสองใบและคิวงานจะเพี้ยน

**หน้าสรุปหลังนำเข้าจะบอกสามอย่าง** — อ่านทุกครั้ง ไม่ใช่กดปิด

- `กำลังดำเนินการอยู่` — PO ที่ยังเดินอยู่ พร้อมบอกว่าค้างที่ขั้นไหน
- `ยอดในไฟล์ไม่ตรงกับในระบบ` — ยอดถูกแก้ที่ SAP หลังรายการเข้าระบบแล้ว
  **ระบบไม่แก้ยอดให้เอง** เพราะอาจมีการตั้งเบิกอิงยอดเดิมไปแล้ว ให้บัญชีตัดสินใจ
- `ข้ามเพราะซ้ำ` — จำนวนแถวที่ไม่ได้สร้าง

### 4.5 เปิดให้แก้ไขทีละใบ

รายการที่นำเข้ามา **ยังแก้ไม่ได้** จนกว่าจะอยู่ในช่วงทดลอง —
เพิ่มเลขที่ต้องการลงแท็บ **`Pilot_Scope`** (คอลัมน์ `deal_no`)
นอกรายการนี้ระบบเปิดให้ดูอย่างเดียว ทำตามขั้นตอนเดิมไปก่อน

### 5.1 สถานะบนหน้าจอตามของจริงแค่ไหน

หลายคนเปิดหน้าค้างไว้ทั้งวัน แล้วเห็นคิวของเมื่อเช้า — คนหนึ่งกดปิดขั้นไปแล้ว
อีกคนยังเห็นว่าเป็นงานตัวเองแล้วทำซ้ำ

หน้าเว็บจึงถามเซิร์ฟเวอร์เบา ๆ ทุก **45 วินาที** ว่าข้อมูลเปลี่ยนไปไหม (ส่งกลับแค่ค่าตรวจสอบสั้น ๆ
ไม่ได้ดึงข้อมูลทั้งชุด จึงไม่หนักโควตา) ถ้าเปลี่ยน หน้าจะขึ้นแถบ **"มีการเปลี่ยนแปลง — กดโหลดใหม่"**
ไม่รีเฟรชทับเอง เพราะผู้ใช้อาจกำลังพิมพ์อยู่

แท็บที่ไม่ได้เปิดอยู่**หยุดถาม**จนกว่าจะกลับมาดู — คนเปิดค้างสิบแท็บจึงไม่กินโควตาทั้งวัน

การกดปุ่มทุกครั้ง**ตรวจจากข้อมูลจริงในชีตเสมอ** ไม่ได้เชื่อสิ่งที่หน้าจอถืออยู่ — ต่อให้เห็นหน้าเก่า
ก็กดซ้ำงานที่คนอื่นทำไปแล้วไม่ได้ ระบบจะตอบว่าขั้นนี้ไม่ใช่ของคุณแล้ว

## 6.5 เว็บค้าง / เปิดไม่ขึ้น — ไล่ตามอาการ

หน้าจอมีตัวจับเวลา 30 วินาทีทั้งตอนเปิดระบบและตอนกดปุ่ม
ถ้าเซิร์ฟเวอร์ไม่ตอบ ระบบจะเลิกรอแล้วบอกสาเหตุ **ไม่ปล่อยให้ค้างเงียบ ๆ**

| อาการที่เห็น | สาเหตุที่พบบ่อยที่สุด | แก้ยังไง |
|---|---|---|
| **หมุนค้างที่ "กำลังเปิดระบบ"** เกิน 30 วิ แล้วขึ้นกล่องแดง | เบราว์เซอร์ล็อกอินหลายบัญชี Google พร้อมกัน | เปิดในหน้าต่าง**ไม่ระบุตัวตน** แล้วล็อกอินบัญชีบริษัทบัญชีเดียว |
| **"อีเมล … ยังไม่มีในระบบ"** | ยังไม่ได้กรอกอีเมลในแท็บ `Users` | หัวหน้าแผนกเพิ่มแถว แล้วรีเฟรช |
| **"ไม่พบแท็บ Users"** | ยังไม่ได้กดเมนู **ติดตั้งระบบ** | กดเมนูติดตั้งระบบในไฟล์ Sheet |
| **"ยังไม่ได้ตั้งค่า Script Property: …"** | ตั้ง properties ไม่ครบ | ดูข้อ 2.2 · กดเมนู **ตรวจความพร้อมก่อนเปิดใช้** |
| **หน้าขาวสนิท ไม่มีอะไรเลย** | `index.html` ตั้งชื่อผิด หรือวางเป็นชนิด Script แทน HTML | ต้องชื่อ `index` และเป็นชนิด **HTML** (ดูข้อ 2.1) |
| **แก้โค้ดแล้วแต่หน้ายังเหมือนเดิม** | ยังไม่ได้ deploy เวอร์ชันใหม่ | Deploy → Manage deployments → ✏️ → Version: **New version** |
| **กดปุ่มแล้วไม่มีอะไรเกิดขึ้น** | มีคำสั่งก่อนหน้าค้างอยู่ | ระบบจะขึ้นข้อความบอก · รอ 30 วิแล้วกดใหม่ |
| **"Drive is not defined"** ตอนนำเข้า Costing | `appsscript.json` ไม่มี Advanced Drive Service | วาง `appsscript.json` ทับใหม่ (ดูข้อ 2.1) |
| **ขึ้นหน้าขออนุมัติสิทธิ์ซ้ำ ๆ** | เพิ่ง Deploy หลังแก้ `oauthScopes` | กด Allow หนึ่งครั้ง เป็นเรื่องปกติ |

**ถ้าไล่แล้วยังไม่หาย** — ให้ IT ดูสองที่นี้ตามลำดับ
1. แท็บ **`Errors`** ในไฟล์ Sheet — บอกเวลา ใคร ฟังก์ชันไหน ข้อความอะไร
2. ตัวแก้ไข Apps Script → **Executions** (แถบซ้าย) — เห็นทุกครั้งที่มีคนเรียก
   พร้อมสถานะ Failed/Timed out และ stack trace เต็ม

**ผู้ใช้แจ้งเองได้ทันที** — ปุ่ม **แจ้งปัญหา** มุมขวาบนใช้ได้แม้ตอนระบบมีปัญหา
ข้อความเข้ากลุ่ม Lark ทันที ไม่ต้องรอสรุปตอนท้ายวัน
